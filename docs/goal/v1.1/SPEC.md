# guitar-hero v1.1 — 구현 명세 (Goal Spec)

- 작성일: 2026-10-08
- 대상 실행자: Claude Code `/goal` 자율 실행 세션 (사람 개입 없음)
- 상태: **승인된 계획**. 이 문서가 v1.1의 단일 진실 원천(single source of truth)이다.
- 이전 버전: v1 명세 `docs/goal/SPEC.md`(+`docs/goal/thresholds.json`)는 **역사 기록으로 보존**한다(수정 금지, 해시 대조). v1.1은 v1 위에 쌓는다. v1 기능·테스트·AC는 v1.1에서도 계속 성립해야 한다(회귀 금지).
- 근거 리서치: `docs/research/01-practice-pedagogy.md`, `02-audio-chord-detection.md`, `03-product-and-stack.md`
- v1.1 키트: `docs/goal/v1.1/`(이 SPEC, `thresholds.json`, `GAP_AUDIT.md`, `traceability.json`, `PROGRESS.md`, `goal-condition.template.txt`, `render-goal.sh`)
- 결정 기록: `docs/goal/DECISIONS.md`(v1과 같은 파일에 이어 쓴다. v1.1 사전 결정은 D-052–D-061)

### v1.1이 v1과 다른 점 (요약)

1. **리서치를 충실히 옮긴다.** v1 SPEC이 리서치(01 §5)에서 빠뜨리거나 약하게 옮긴 연습·규칙을 되살린다. 차이 목록과 처리 결과는 `GAP_AUDIT.md`, 리서치 권고 → SPEC 절 → AC 대응은 `traceability.json`.
2. **v1 결함을 고친다.** SPEC에 있었지만 구현이 연결하지 않았거나 잘못 연결한 것(코드 기억 퀴즈가 루틴에 없음, "코드 진행" 모드가 코드 1개, 쌍 배정 교착, 드릴의 기술 슬롯 독점, 템포가 매일 60에서 다시 시작, 곡 복습이 영영 배정되지 않음, 정체 감지·G 전환·스트레칭 시작 프렛·루틴 편집의 미연결).
3. **Stage 8–11을 진행 가능하게 연다**(초급 2: 드론 코드·스케일·F·파워코드·7th·블루스). v1이 범위 밖으로 둔 E3·E9–E12·지판 음이름 확장·인터벌 귀 훈련·반주(play-along)·셈여림도 넣는다.
4. **판정 정답이 없는 기능은 베타**로 넣는다: 버징, 스트럼 방향(업/다운), 해머온(레가토) 검출, 팜뮤트, 셈여림. 측정·보고만 하고 통과 기준(게이트)·진급 판정에 쓰지 않는다(§10.11, §14.8).
5. **같은 종류의 누락이 다시 생기지 않게 하는 테스트**를 넣는다: 커리큘럼 "배울 것"의 연습 연결, 진급 규칙 ↔ 루틴 대응, 28일 루틴 시뮬레이션, 가상 학습자 진급 도달 시뮬레이션, SPEC이 요구한 함수의 실제 호출 검사, 리서치 추적표 완전성(§14.9).

## 0. 이 문서를 읽는 법

1. **처음 시작할 때**: §0–§3을 정독하고 `GAP_AUDIT.md`를 한 번 읽는다. 그다음 §16 마일스톤 순서(M9→M15)대로 진행한다. 각 마일스톤에 들어갈 때 그 마일스톤이 참조하는 절을 다시 읽는다.
2. **매 턴 시작 시**: `docs/goal/v1.1/PROGRESS.md`를 먼저 읽는다. 컨텍스트가 압축(compaction)된 뒤에도 PROGRESS.md만 보면 이어서 할 수 있어야 한다.
3. **우선순위**: 이 SPEC > `DECISIONS.md`에 기록한 결정 > 리서치 문서 > v1 SPEC > 일반 관행. 리서치 문서와 SPEC이 다르면 SPEC을 따른다. 이 SPEC이 v1 SPEC과 다르면 이 SPEC을 따른다.
4. **"설계값"** 이라고 표시된 수치는 리서치에 근거 숫자가 없어 이 SPEC이 정한 값이다. 앱 설정에서 조정 가능해야 하지만, **§14의 테스트 임계값과 테스트 매트릭스, `v1.1/thresholds.json`은 설계값이 아니라 고정 계약**이다.
5. 이 문서의 코드 조각은 인터페이스와 의도를 보여 주는 스케치다. 이름과 시그니처는 바꿔도 되지만 **의미(semantics)는 지켜야 한다.** 바꾸면 DECISIONS.md에 기록한다.
6. 이미 있는 v1 구현을 먼저 읽고 재사용한다. v1 구조(`src/dsp`, `src/domain`, 플러그인 레지스트리, `generateRoutine`, `pluginParamsFor`, 벤치마크 하네스)를 뒤엎지 않는다. 새 것은 그 확장점에 붙인다.

## 1. 제품 개요

### 1.1 한 문장

**완전 초보 성인이 어쿠스틱 기타를 "체계적으로" 배우도록, 매일의 연습 루틴을 짜 주고, 마이크로 듣고 정직하게 피드백하며, 진도를 숫자로 보여 주는 local-first 웹앱.** v1.1은 초급 1(Stage 0–7)에 초급 2(Stage 8–11)를 더한다.

### 1.2 사용자 (단 한 명)

v1 SPEC §1.2와 같다(완전 초보, 스틸 줄 어쿠스틱, 표준 튜닝, MacBook·iPad·iPhone, 한국어 UI, 로컬 저장, 앱 자체 콘텐츠).

### 1.3 핵심 약속 (모든 설계 판단의 기준)

v1 SPEC §1.3의 다섯 가지(정직한 피드백, 체계적 루틴, 손은 기타 위에, 자동 판정은 사람이 고칠 수 있다, 데이터는 사용자 것)를 그대로 지킨다. v1.1에서 하나를 더한다.

6. **화면이 약속한 것은 연습으로 이어진다**: 커리큘럼이 "배울 것"으로 보여 주는 모든 항목은 루틴 안의 연습이나 자가 체크로 실제로 다뤄진다. 진급 기준에 쓰이는 모든 지표는 루틴만 따라가도 채울 수 있다.

### 1.4 v1.1 성공 기준 (요약 — 정식 기준은 §17)

- Stage 0–11의 커리큘럼·루틴·연습·진급(초급 1 졸업 시험, 초급 2 수료)이 처음부터 끝까지 동작하고, 리서치 01 §5의 연습·규칙이 `traceability.json`대로 구현되거나 근거와 함께 제외된다.
- 루틴만 따르는 가상 학습자가 Stage 0부터 11까지 교착 없이 진급한다(§14.9).
- 마이크 판정이 v1의 모든 임계값과 v1.1의 새 임계값(단음 시퀀스, 스윙, 반주 누출)을 통과한다. 베타 판정은 지표를 보고한다.
- MacBook/iPad/iPhone 화면에서 깨지지 않고, 키보드·페달만으로 하루 루틴(20분, Stage 8+는 30분)을 끝까지 진행할 수 있다.
- `npm ci && npm run verify` 한 번으로 모든 게이트가 통과한다.

## 2. 자율 실행 규칙 (Operating Rules)

이 절은 사용자의 전역 규칙(`~/.claude/CLAUDE.md`)을 **이 goal 실행에 한해** 구체화한다. 충돌하면 이 절이 우선한다(사용자가 이 goal을 위해 명시적으로 승인한 내용이다).

### 2.1 계획과 질문

- 이 SPEC이 승인된 계획이다. **Plan Mode에 들어가지 않는다. `/taskloop`도 쓰지 않는다.**
- **사용자에게 질문하지 않는다**(AskUserQuestion 금지 — 아무도 답하지 않는다). 모호하면 SPEC의 기본값을 따르고, 기본값이 없으면 가장 보수적이고 되돌리기 쉬운 선택을 한 뒤 `DECISIONS.md`에 기록한다.

### 2.2 Git

- 작업 브랜치: **`feat/practice-app-v1.1`**. `feat/practice-app-v1`의 `5e94332`에서 분기하고, v1.1 키트를 담은 첫 커밋이 이미 있다. 이미 있으면 그 브랜치에서 이어 간다.
- `feat/practice-app-v1`은 `5e94332`에서 움직이지 않는다(커밋·리셋 금지). `main`은 `9e7eda6` 그대로다.
- **마일스톤이 끝나고 `npm run verify`가 통과했을 때만** 커밋한다. 커밋 메시지: `M<n>: <요약>` + 본문에 완료한 AC ID 목록. WIP 커밋(`wip(M<n>): ...`)은 verify가 깨져 있어도 되지만 마일스톤 종료 커밋은 반드시 verify 통과 상태여야 한다. 히스토리를 고쳐 WIP를 지우지 않는다.
- **금지**: `git push`, 원격 추가, `main`·`feat/practice-app-v1` 수정·병합·리베이스, `--force`, `reset --hard`(자기 WIP를 되돌릴 때 제외), 브랜치 삭제, 태그 push, 히스토리 재작성.
- `git commit` 전에 README 반영 여부를 확인한다. 기능/스크립트/설정이 바뀌면 README를 갱신한다.

### 2.3 범위 밖 행동 금지

- 배포 실행 금지(설정 파일과 문서만). 외부 서비스 계정 생성·로그인 금지.
- 레포 밖 파일 수정 금지. 예외: npm 캐시, Playwright 브라우저 설치, 레포 안 `data/`(gitignore) 다운로드, §2.5의 vault 노트(`~/Documents/vault/` 아래 새 노트 생성, 그리고 양방향 링크를 위해 기존 노트의 `## 관련` 절에 링크 한 줄 추가만).
- `~/.claude/` 설정, 훅, 스킬, 권한 설정을 바꾸지 않는다.
- 네트워크 허용 범위: npm registry, Playwright 브라우저 다운로드, Zenodo(GuitarSet), 라이브러리 공식 문서 조회. 사용자 데이터·녹음을 외부로 보내는 코드·요청 금지(텔레메트리 없음).

### 2.4 품질 무결성 (가장 중요)

- **수정 금지 파일**: `docs/goal/SPEC.md`, `docs/goal/thresholds.json`(v1), `docs/goal/v1.1/SPEC.md`, `docs/goal/v1.1/thresholds.json`, `docs/goal/v1.1/traceability.json`, `docs/goal/v1.1/GAP_AUDIT.md`. 최종 검증에서 SHA-256을 대조한다.
- §14의 **임계값, 테스트 매트릭스 최소 차원, split 시드 범위, E2E 단언을 완화하지 않는다.** v1에서 만든 테스트와 무결성 테스트를 약하게 고치지 않는다(파일 경로를 v1.1 계약으로 바꾸는 것은 허용 — §14.0).
- **v1 테스트 갱신 규칙**: v1.1이 의미를 바꾼 규칙(§7.1 recall·쌍 55초·기준 정의, §7.2 Stage 8–11 진행, §7.3-2·3·6 템플릿·쌍·복습, §7.4, §7.5 곡·카드, §11.10 곡 단계)을 단언하는 v1 테스트만 v1.1 의미로 다시 쓴다. 바꾼 테스트는 파일·테스트 이름·근거 SPEC 절을 DECISIONS의 한 항목("v1 테스트 갱신 목록")에 모두 적는다. 그 밖의 v1 단언은 바꾸지 않는다(AC-P10).
- **베타 지표는 게이트가 아니다**: `thresholds.json`의 `beta` 구획 값은 목표치일 뿐 verify의 성패를 바꾸지 않는다. 반대로 하드 지표를 베타로 옮기는 것은 금지다.
- DSP 파라미터 튜닝은 **dev split에서만** 한다. test split은 마일스톤 종료와 최종 검증에서만 돌린다(개발 중에는 `bench:dsp:dev`).
- 최종 상태에 `.skip`, `.only`, `test.fixme`, `// @ts-ignore`, `// @ts-expect-error`(타입 테스트 제외), 사유 없는 `biome-ignore`가 없어야 한다.
- 임계값을 도저히 못 맞추면: 원인 분석과 시도를 `DECISIONS.md`에 쓰고 SPEC 안의 대안 알고리즘을 시도한다. **임계값을 낮추거나 매트릭스를 줄이는 것은 해결책이 아니다.**
- 의존성 라이선스: MIT/BSD/ISC/Apache-2.0/0BSD/MPL-2.0(수정 없이)/CC0/Unlicense만. **GPL/LGPL/AGPL 금지**. `npm run licenses`가 강제한다.

### 2.5 진행 관리

- 매 턴 끝에 `docs/goal/v1.1/PROGRESS.md`를 갱신한다: 현재 마일스톤, 완료한 AC(증거 포함), 다음 할 일 3개 이내, 막힌 점. **예외**: §16.2-3의 최종 verify 이후 마지막 턴에는 갱신하지 않는다(작업 트리를 깨끗하게 유지, AC-P9의 증거는 직전 verify + 최종 출력).
- 같은 원인으로 마일스톤 verify가 3회 연속 실패하면 분석을 DECISIONS.md에 쓰고 접근을 바꾼다(SPEC 범위 안에서 더 단순한 대안). /goal의 "턴"은 거시 단위라 턴 수로 정체를 판단하지 않는다.
- 턴을 끝낼 때 백그라운드 프로세스를 남기지 않는다. E2E 서버는 Playwright `webServer`로 띄운다.
- **10분 넘는 명령**(전체 `npm run verify`, 첫 GuitarSet 다운로드)은 `run_in_background`로 실행하고 완료 알림을 받은 뒤 결과를 확인한다. verify가 도는 동안 작업 트리를 수정하지 않는다. verify는 추적 파일을 바꾸지 않는다(벤치 보고서는 `bench-results/` 사본, D-050).
- 서브에이전트는 써도 된다. 두 에이전트가 같은 파일을 동시에 고치지 않게 한다. 마일스톤 **M10·M12·M15 끝**에는 리뷰 서브에이전트(`code-reviewer`)로 변경분을 검토하고, 확인된 결함은 고친다. 리뷰 에이전트에게 레포 안에 파일을 만들지 말라고 지시하고, 만들었으면 지운다(`.claude/agent-memory/`는 키트 커밋에서 이미 `.gitignore`에 있다). 새 생성 산출물(fixture 등)은 커밋 대상이 아니면 `.gitignore`에 넣어 최종 `git status --short`를 깨끗하게 유지한다.
- 사용자 전역 규칙의 vault 기록은 **최종 턴 직전 1회**(세션 요약 + 핵심 결정 2–3개)로 한다.

### 2.6 진행 예산

- 전체 상한은 **1000턴**이다. /goal의 턴은 거시 단위(한 턴에 여러 마일스톤이 진행될 수 있음)라 마일스톤별 턴 예산은 두지 않는다.
- §16.1 축소 조건은 턴 수가 아니라 **"M13 커밋 이후, 같은 하위 항목 때문에 마일스톤 verify가 3회 연속 실패"**다.

## 3. 범위

### 3.1 v1.1에 포함 (In)

v1 SPEC §3.1 전부에 더해:

## 6. 음악 도메인과 콘텐츠

### 6.1 튜닝과 줄 번호 규약

- 내부 배열 인덱스 `i = 0..5`는 **6번 줄(저음 E)부터 1번 줄(고음 E)** 순서다. UI 표기는 기타 관례대로 "6번 줄 … 1번 줄"을 쓴다. 이 변환은 한 곳(`domain/strings.ts`)에서만 한다.
- 표준 튜닝 MIDI: `[40, 45, 50, 55, 59, 64]` (E2 A2 D3 G3 B3 E4). `f = 440 · 2^((m − 69)/12)`.
- 튜닝은 `Tuning { id, name, openMidi: number[6] }`로 표현하고 capo는 `+c`로 처리한다(v1 UI는 표준 튜닝·capo 0만 노출, 모델은 일반형).
- 캘리브레이션에서 측정한 줄별 cents 오프셋 `δ[i]`를 기대 주파수에 반영한다: `f0[i] = 440 · 2^((m[i] − 69)/12) · 2^(δ[i]/1200)`.

### 6.2 보이싱 모델

```ts
type Fret = number | 'x';                 // 'x' = 치지 않는 줄(뮤트), 0 = 개방현
type FingerId = 1 | 2 | 3 | 4 | 'T';
interface ChordVoicing {
  id: string;                             // 'C', 'G-3f' ...
  symbol: string;                         // tonal로 해석 가능한 코드 심볼 ('C', 'G', 'Fmaj7', 'G5')
  nameKo?: string;                        // 선택: 'G (두 손가락)'
  frets: readonly Fret[];                 // 길이 6, 6번→1번 줄
  fingers: readonly (FingerId | 0 | null)[]; // 0 = 개방, null = 뮤트
  barres?: readonly { fret: number; fromIdx: number; toIdx: number; finger: FingerId }[];
  baseFret: number;                       // 다이어그램 시작 프렛(1 = 너트)
  stage: number;                          // 도입 스테이지
  tags: readonly string[];                // ['open', 'beginner1'] ...
}
```

파생 함수(순수, `domain/voicing.ts`):
- `expectedNotes(voicing, tuning, capo, deltaCents?) → { idx, midi, f0 }[]` (x 줄 제외)
- `mutedStrings(voicing) → idx[]`
- `anchors(a, b) → { finger, idx, fret }[]` : 두 보이싱에서 **같은 손가락이 같은 (줄, 프렛)** 에 있으면 앵커. 같은 손가락이 같은 줄에서 프렛만 바뀌면 `slides`로 별도 반환. 앵커/공중 체인지 드릴(§11 E4)이 이것을 쓴다. 손으로 앵커 메타데이터를 쓰지 않는다.
- `partialCollisionMap(voicing, tuning, params) → { idx, verifiable: boolean, independentPartials: number[] }[]` (§6.3)

### 6.3 스트럼 모드 검증 가능성(partial 충돌 맵) — 고정 규칙

스트럼(한 번에 긁기)에서는 줄 하나가 뮤트돼도 다른 줄의 배음이 그 주파수를 채울 수 있다(예: open C의 2번 줄 C4 = 5번 줄 C3의 2배음). 그래서 보이싱마다 "스트럼으로 확인 가능한 줄"을 미리 계산한다.

**기본 규칙(v1 고정)**:
- 줄 `s`의 partial `h = 1..8` (주파수 ≤ 5 kHz, inharmonicity `B = 5e-5` 반영)
- partial이 **다른 모든 연주 줄 `o ≠ s`의 partial `k = 1..16`** 중 하나와 ±35 cents 안이면 "충돌"
- `f0[s] < 120 Hz`인 줄은 `h = 1`을 독립 partial로 세지 않는다(노트북·휴대폰 마이크의 저역 roll-off)
- **독립 partial이 2개 이상이면 `verifiable = true`**

이 규칙을 바꾸려면 DECISIONS.md에 근거를 쓰고, §14.3의 "검증 가능 줄 커버리지"가 기본 규칙보다 **떨어지지 않아야** 한다(커버리지를 줄여 지표를 좋게 만드는 것 금지).

단위 테스트 필수 사례: open C(`x32010`)에서 5번 줄(C3)은 verifiable, 2번 줄(C4)은 verifiable이 아니다. UI(코드 라이브러리, Chord Perfect 화면)는 verifiable이 아닌 줄에 "스트럼으로는 확인 불가 — 한 줄씩 튕겨서 확인" 표시를 한다.

  1. **위아래**: 모든 음을 올라간 뒤 맨 위 음을 반복하지 않고 내려온다(12음 모양 → 23음).
  2. **방향 바꾸기**: 모양 안에서 한 음씩 움직이되, 각 음 뒤에 1/4 확률로 방향을 바꾼다(맨 끝에서는 반드시 바꿈). 길이 = 2 × 음 수 − 1.

  4. **3도**: 1-3, 2-4, 3-5 … 로 올라간 뒤 대칭으로 내려온다.
  5. **4음씩**: 1-2-3-4, 2-3-4-5 … 로 올라간 뒤 대칭으로 내려온다.

     - 먼저 **위험 쌍**: 현재 스테이지 진급 규칙이 요구하고 아직 통과하지 않은 쌍 중 마지막 배정 후 5연습일 이상 지났거나 한 번도 배정되지 않은 쌍. 그중 최근 3회 중앙값이 가장 낮은 것(한 번도 안 한 쌍이 먼저).
     - 위험 쌍이 없으면 due 쌍 복습(먼저 due된 것).
     - 그것도 없으면 아직 통과하지 않은 필요 쌍 중 중앙값이 가장 낮은 것.
     - 그것도 없으면 순환 규칙.
   - **순환 규칙**: 해금된 쌍(Stage 0–7은 핵심 25쌍 중, Stage 8–11은 §6.5 그 스테이지 쌍) 중 마지막 배정이 가장 오래된 것.
   - **E3 규칙**(Stage 8–11): OMC→PFC 처방 쌍이 있으면 그 쌍. 없으면 그 스테이지 쌍 중 E3를 졸업하지 않았고 마지막 배정이 가장 오래된 쌍(Stage 10·11은 그 스테이지 쌍 중 E2 ≥30을 통과한 쌍, 없으면 Stage 8 쌍).
   - **겹침**: 같은 쌍이 두 칸에 들어가면 뒤 칸은 다음 후보로 넘긴다. 다음 후보가 없으면 같은 쌍의 반대 방향을 쓴다. 방향은 그 쌍에서 최근에 덜 한 방향.
   - **배정 보장**: "현재 스테이지 진급 규칙이 요구하고 아직 통과하지 않은 쌍"은 연습일 7일 안에 1회 이상 배정된다(§14.9가 검사). 진입 시점의 이런 쌍 수는 Stage 1: 1, 2: 3, 3: ≤5, 5: ≤10, 6: ≤7, 11: 8로 주 14칸 안에 들어간다.
   - 하루 1분 체인지·PFC 총 6회 상한 [설계값]. 통증 ≥5 보고 다음 날은 상한 3회.
4. 같은 연습 항목을 연속 배치하지 않는다(interleave). 단 신규 코드의 첫 노출은 짧은 blocked 연습 후 교대.
5. 마지막 연습 후 3일 초과 공백이면 첫 블록을 직전 스테이지 복습으로 바꾼다 [근거].
6. **복습 배정**(v1 규칙 6 대체 — 곡 복습이 영영 못 들어가고 다른 복습까지 막던 결함 수정):
   - **같은 subjectKey면 복습으로 인정**: 그날 어느 블록에든 due 항목과 같은 subjectKey의 실행이 배정되면, 그 due 복습은 배정된 것으로 본다(실행 결과로 복습 성공·실패를 기록).
   - **종류별 칸**:
     - 코드 → E1 "최약·복습" 칸(due 코드가 있으면 최약보다 먼저)
     - 쌍 → 1분 체인지 슬롯 2의 둘째 순위(규칙 3)
     - 패턴 → 리듬 블록 순환의 ③순위
     - 스케일 단계·리프 → 스케일·기술 블록 순환의 ③순위(규칙 2)
     - 곡 → Stage 1–6은 곡 블록의 앞부분(복습 곡 연주 단계 1회 후 이번 곡), Stage 7+는 레퍼토리 블록
   - **지식 카드**: Q2 코드 카드와 Q3·Q4 카드는 그 퀴즈 실행 안에서 due 카드를 먼저 묻는다. 그날 순환에 Q3·Q4가 없고 그 종류의 due 카드가 있으면 Q2 블록 60초를 Q2 30초 + 그 퀴즈 due 카드 30초로 나눈다.
   - **밀림 처리**: 한 칸에서 못 한 due 항목은 다음 세션으로 넘기되 뒤 항목을 막지 않는다. 종류별로 먼저 due된 것이 먼저 배정된다(FIFO). 배정 지연의 상한은 §14.9가 검사한다.
   - **처방**(§7.4): Stage 1–7에서는 기술 슬롯의 ②순위로 들어간다(OMC→PFC 처방이면 그 칸에서 E3 60초 + 휴식 30초). Stage 8–11 OMC→PFC 처방은 E3 칸이다. 처방은 순환 보장 항목을 몰아내지 않는다(v1 결함 수정).
7. 직전 세션 통증 ≥5/10이면 손끝 부하 항목(E1, E2, E3) 블록 시간을 50%로 줄이고(15초 단위 반올림, 최소 30초) E11·E12는 그날 빼며, 빈 시간은 채우지 않는다. "날카로운 통증·저림·관절/손목 통증" 보고 시 오늘 루틴 대신 휴식 안내(의학적 조언 아님 고지) [근거]. 감량은 실행 파라미터에 반영된다(v1 수정, `item.durationSec`이 유일한 길이 출처).
8. 연속 30분 연습 시 휴식 알림 [근거].
9. **루틴 편집**: 사용자가 오늘 루틴의 항목을 추가/삭제하거나 블록 시간을 바꿀 수 있다.
   - 편집본은 템플릿으로 저장된다(`routines` 테이블, `source: 'user'`).
   - 저장된 템플릿이 있으면 다음 세션부터 그 스테이지에서 템플릿의 항목 구성을 쓴다. 쌍·코드·BPM 같은 파라미터는 규칙 3·6·10으로 다시 채운다.
   - "기본으로 되돌리기"로 템플릿을 지운다. 편집본도 규칙 7(통증)과 1(4주 상한)을 따른다. 편집으로 빠진 순환 항목·필요 쌍은 보장 검사에서 제외된다(§14.9는 기본 템플릿으로 검사).
10. **파라미터 의미**(v1 결함 수정, §14.9가 검사):
    - **E5 모드**: 순환 목록에 모드가 적힌 항목은 그 모드가 열려 있으면 그 모드, 아니면 열린 가장 뒤 모드다(§6.10 모드 사다리). progression 모드는 스테이지 `rhythmProgression`(코드 2개 이상)을 넘긴다.
    - **템포**: 템포가 있는 항목(E5·E6·E8·E9·E10·E17·E11)의 BPM은 그 subject의 **사다리 현재 BPM**(§7.4 스킬 상태)이고, 처음이면 시작 BPM이다. "매일 60에서 다시 시작"하지 않는다. 단 활성 "시작 BPM −10" 처방(§7.4)이 있는 subject는 사다리 현재 BPM − 10이다.
    - **E7**: 시작 프렛은 `nextStretchStartFret`(최근 실행 기록)으로 정한다.
    - **암기 기준이 걸린 스케일**(Stage 9 c-major-open): 그 스케일의 3번째 배정부터 암기 통과 전까지 1단계 `tabHidden: true`로 배정한다.
    - **Q3**: Stage 10 Q3 `strings65`는 `questions: 20`으로 배정한다(블록 60초는 목표 시간이고 실행은 20문항을 끝까지 한다).
    - **곡 블록**: 곡의 가장 높은 열린 단계(§11.10)로 배정한다.
11. **분할(Stage 8–11)**: 30분 루틴은 템플릿 중간(리듬 블록 뒤)에 "여기서 나눠 하기" 지점을 둔다. 사용자가 그 지점에서 세션을 끝내면 같은 날 남은 절반을 홈에서 "이어서 하기"로 시작할 수 있다(날짜가 바뀌면 사라짐). 두 절반은 한 세션 기록으로 합친다.
12. **블록 시간 = 목표 연습 시간**(리서치 01:156 타임박싱; D-046 보완): 마디·문항 단위 항목(E5·E6·E8·E9·E10·E17·Q*·S)은 한 번 실행이 끝났을 때 블록 시간이 남았으면 결과 요약과 함께 "이어서 한 번 더"를 기본 동작으로 제시한다(Space = 다시, Enter = 다음 항목 — v1 D-051의 키 그대로). 다음 반복은 사다리 결과 템포를 쓴다. 블록 시간이 다 되면 짧은 신호음 + 큰 시각 표시("블록 끝")를 낸다. 강제로 끊지는 않는다.
13. **블록 사이 휴식**(리서치 01:178): 블록이 바뀔 때 5초 전환 화면(다음 항목 이름·다이어그램)을 보여 준다(블록 시간에 넣지 않는다). 설정에서 끌 수 있다. 1분 체인지 사이 30초 휴식은 그대로다.
14. 같은 입력(시드 포함) → 같은 출력. 단위 테스트로 규칙 1–13을 각각 검증하고, §14.9 시뮬레이션이 여러 날에 걸친 성질을 검증한다.

### 7.4 진급 엔진 (`domain/progression.ts`)

- 스테이지 진급 기준(§7.1)을 **데이터로 표현**한다(`UnlockRule[]`). 코드에 스테이지별 if문을 쓰지 않는다. v1 규칙 종류에 더한다:
  - `daysInStageAtLeast { days }` — Stage 8–11 14일.
  - `recallPassed { voicingIds }` — §7.1 Q2 정의(서로 다른 2일 3초 안 정답).
  - `pairsPassedAtLeast { pairs, minCount }` — 쌍 집합 중 minCount개 이상 ≥30(Stage 11은 8개 중 6개).
  - `songsCompletedAtLeast { filter, count }` — 연주 모드 완주한 서로 다른 곡 수(filter: 스테이지, 포함 코드).
  - `scaleStepGraduated { scaleId, step, bpm }`, `chordCleanRatioAtLeast { voicingIds, window, ratio }`, `quizRunAtLeast { scope, questions, accuracy, medianReactionMsMax }`, `scaleMemorized { scaleId }`.
- **사다리 상태**: 템포 사다리가 있는 subject(`strum:<P>:<mode>`, `onebeat:<prog>`, `altpick:<string>`, `chromatic:<startFret>`, `scale:<id>:s<step>`, `riff:<id>`, `hammer:<pair>`)마다 스킬 상태에 `currentBpm`과 최근 판정을 저장한다. 사다리 규칙은 각 연습 절(§11)을 따른다. 루틴이 이 값을 읽는다(§7.3-10).
- **조건부 진급**(01:288, 3주):
  - 쌍 정체(3주) = 오늘을 끝으로 하는 21일 창에서 그 쌍의 1분 체인지 실행이 6회 이상이고, 창 안 첫 3회 중앙값 대비 마지막 3회 중앙값 상승이 2 미만이며, 창 안 첫 실행이 오늘보다 14일 이상 앞선다.
  - 쌍 기준 외의 다른 기준을 모두 채웠고, 남은 미통과 필요 쌍이 모두 3주 정체면 "조건부 진급 가능"을 제안한다. `pairsPassedAtLeast { minCount }` 규칙은 minCount까지 모자란 수만큼의 미통과 쌍이 모두 정체일 때다.
  - 수락하면 다음 스테이지에 그 쌍들의 처방(아래 표의 쌍 행)을 **추가**한다(순환 보장을 몰아내지 않는다 — §7.3-6). 처방은 8세션 뒤 또는 그 쌍이 ≥30을 통과하면 만료된다.
- **정체 감지**(리서치 01:389 "2주"): 매 세션 시작 시 `detectStagnation`을 실제로 호출한다. 정체 = 오늘을 끝으로 하는 14일 창에서 그 subject 실행이 4회 이상이고, 창 안 첫 실행(또는 첫 3회 중앙값, 쌍·코드) 대비 마지막 값의 개선이 아래 표의 기준 미만이며, 창 안 첫 실행이 오늘보다 9일 이상 앞선다. "핵심 지표"와 기준(고정):

| subject | 핵심 지표 | 2주 동안 개선 없음 = | 처방 |
|---|---|---|---|
| 쌍(E2) | 최근 3회 중앙값 | +2 미만 | E3 정확 빠른 체인지(같은 쌍) + E4 앵커/공중 드릴 — "OMC → PFC 전환" |
| 쌍(E3) | clean_rate | 0.5 미만에서 +0.1 미만 | E2로 돌아가기 — "PFC → OMC 전환" |
| 코드(E1) | 최근 10회 clean 비율 | +0.1 미만 | 한 줄씩(Mode A) 모드 + 그 코드의 코칭 팁 카드 |
| 패턴·스케일·리프·교대 피킹 | 사다리 현재 BPM | +5 미만 | 1주 동안 시작 BPM을 현재 −10으로(사다리 상태는 보존) |

  처방은 홈 화면 "추천" 카드와 루틴(§7.3-6: Stage 1–7은 기술 슬롯 ②순위, Stage 8–11의 OMC→PFC 처방은 E3 칸)으로 나온다. 같은 subject에 처방은 한 번에 하나다.
- 사다리 정체(패턴·스케일·리프·교대 피킹)는 그 subject가 졸업했거나 사다리 현재 BPM이 그 연습의 목표 BPM 이상이면 판정하지 않는다.
- 정체(2주, 처방)와 조건부 진급(3주, 진급 제안)은 다른 규칙이다(리서치 01:288 대 01:389의 기간 차이를 이렇게 정한다, D-056).
- **코드 습득/숙달**: v1 그대로(최근 10회 중 clean ≥5 습득, ≥8 숙달). clean = Mode A 전부 OK 또는 수동 줄별 체크 전부 clean.
- **G 보이싱 전환**: §6.4. 습득 판정 시 `suggestedGVoicing`을 실제로 호출해 홈에 제안 카드를 띄운다.
- **E7 시작 프렛**: 통증 ≤2로 3세션 완료하면 1칸 낮추고(`nextStretchStartFret`을 실제로 호출), 1프렛 도달 시 졸업 [근거: 01:322].

### 7.5 복습 큐 (간격 반복)

- 졸업한 항목(코드, 쌍, 패턴, 스케일 단계, 리프)은 복습 큐로 간다. 간격: 1 → 3 → 7 → 14 → 30 → 90일. 복습 실패 시 한 단계 후퇴 [설계값, 01:269].
- **곡**: 연주 모드에서 멈춤 0으로 완주한 곡이 레퍼토리에 들어가고(리서치 01:158 "공연 수준 도달 후"), 간격은 1주 → 2주 → 1개월 → 3개월 → 6개월 → 1년 [근거: 01:363]. v1의 "학습 모드 완주 1회로 졸업"을 대체한다.
- **지식 카드**(리서치 01:353, 03:113): Q2 코드 카드(보이싱마다 1장), Q3 음 카드(위치마다 1장). 정답 & 3초 미만 → 다음 간격(위 사다리), 정답 & 3초 이상 → 같은 간격 유지, 오답 → 1일로 리셋. Q2·Q3 실행은 due 카드를 먼저 묻는다.
- **복습 배정**: 별도 "복습 슬롯"을 두지 않고 같은 종류의 블록에서 한다(§7.3-6, 리서치 03:114의 5분 슬롯 대신 — 20분 세션에 5분 슬롯을 따로 두면 곡 9분과 리서치 루틴 블록을 지킬 수 없다, D-058).
- 스트릭은 **주 단위**(주 4회 이상 연습한 주의 연속 수) [03 §2.5].

- 시험 항목 5의 "악보 숨김 완주"는 §11.10의 숨김 단계 완주(멈춤 ≤ 1)로 기록된 곡을 센다(자가 보고는 마이크가 없을 때만).

### 7.7 초급 2 수료 (Stage 11 → 수료)

- 리서치에 초급 2 시험은 없다(01 §5.5는 초급 1만). 그래서 **Stage 11 진급 기준 충족 = 초급 2 수료**로 한다(D-057).

## 8. 오디오 엔진

근거: 리서치 02 §1, 03 §2.1–2.4.

### 8.1 캡처

```ts
const stream = await navigator.mediaDevices.getUserMedia({
  audio: {
    echoCancellation: false, noiseSuppression: false, autoGainControl: false,
    channelCount: { ideal: 1 },
    deviceId: preferredDeviceId ? { exact: preferredDeviceId } : undefined,
  },
});
```
- `sampleRate`는 지정하지 않는다. `AudioContext`는 `{ latencyHint: 'interactive' }`로 만들고, DSP 파라미터는 모두 ms/Hz로 정의해 `ctx.sampleRate`로 변환한다. **모든 DSP 코드와 테스트는 44.1 kHz와 48 kHz 둘 다**에서 동작해야 한다.
- `track.getSettings()` 결과(echoCancellation/noiseSuppression/autoGainControl/sampleRate/deviceId/label)를 세션 진단 정보로 저장하고, 설정 > 진단 화면에 보여 준다. 처리가 꺼지지 않았으면 경고한다.
- iOS/iPadOS: `getUserMedia` 전에 `if ('audioSession' in navigator) navigator.audioSession.type = 'play-and-record'`. `AudioContext.resume()`은 사용자 탭 이벤트 안에서 호출한다.
- Bluetooth 입력 장치(이름에 AirPods/Bluetooth/BT 등)가 선택되면 "내장 마이크를 권장" 경고를 띄운다.
- 마이크는 연습 화면에 들어갈 때 켜고 나갈 때 끈다(배터리, 프라이버시 표시등). 권한 거부·장치 분리·`AudioContext` interrupted 상태를 처리하고 사용자에게 복구 방법을 보여 준다.

### 8.2 AudioWorklet (capture-processor)

- 128-sample 블록마다: 4초 ring buffer 적재, 블록 RMS/peak, 클리핑(|x| > 0.98) 감시, onset ODF 계산(§10.4, hop 256 @48k에 해당하는 샘플 수, 비정수는 누적 처리).
- 레벨 미터용 값(RMS dBFS, peak)은 약 30 Hz로 main에 보낸다.
- onset 후보가 나오면 `{ frame, time, strength }`와 해당 구간 샘플(onset −500 ms ~ +400 ms, Transferable)을 Worker로 보낸다.
- hot path에서 메모리 할당 금지(사전 할당 버퍼). 블록당 평균 처리 시간 ≤ 0.3 ms(Node 마이크로벤치, §14.3).
- TS로 작성하고 Vite 8에서 dev/build 양쪽에 번들되는지 M0 스파이크에서 확인한다(`?worker&url` 또는 `new URL(..., import.meta.url)` — 확인된 방법을 DECISIONS에 기록).

### 8.3 DSP Worker

- `dsp/`의 순수 함수를 호출하는 얇은 어댑터. 메시지 프로토콜은 판별 유니온 + zod 검증.
- 요청: `verifyPluck`, `verifyStrum`, `classifyPair`, `classifySet`, `tune`, `estimateRtt`, `analyzeTiming`. 응답에는 항상 `detectorVersion`과 처리 시간이 들어간다.

### 8.4 메트로놈 (`audio/metronome.ts`)

- "A Tale of Two Clocks" lookahead: 타이머(가능하면 Worker 안의 `setInterval` 25 ms)가 깨어날 때마다 `ctx.currentTime + 0.1 s` 안에 들어오는 클릭을 오디오 클럭 기준으로 예약한다. 메인 스레드가 끊길 수 있으면 lookahead 0.25 s / 주기 0.2 s.
- 클릭 음색: 2–4 kHz 대역의 짧은(≤ 15 ms) 합성음. 1박 악센트는 다른 음높이 + 큰 시각 표시. 오디오 파일 없이 합성.
- 기능: 시작/정지, BPM 30–240, ±1/±5, 탭 템포(최근 4간격 평균, 2초 무입력 리셋), 박자 4/4·3/4·6/8, 서브디비전, 카운트인 1–2마디(측정에서 제외), 음소거 마디(N마디마다 M마디 무음), 템포 사다리(시작/목표/증분/조건), 시간·마디 제한 자동 정지, **시각 전용 모드**(소리 없이 펄스만 — 클릭이 마이크로 새는 것을 원천 차단).
- 예약한 클릭 시각 목록은 판정기(Mode D)와 공유한다: 클릭 누출 마스킹, 그리드 기준 시각.
- 시각 펄스는 rAF에서 `currentTime`과 비교해 이미 지난 클릭만 그린다.
- 단위 테스트: 가짜 AudioContext 클럭 + 지터가 있는 타이머 콜백(0–150 ms 지연, 가끔 1 s 정지)으로 10분을 시뮬레이션해도 모든 클릭이 그리드 시각에 정확히(부동소수점 오차 내) 예약되고, 누락·중복이 없다. 템포 변경은 다음 박부터 적용된다.

### 8.5 타이머

- 경과 시간은 항상 **시계 차이**(`performance.now()` 또는 `ctx.currentTime`)로 계산한다. 틱 횟수를 누적하지 않는다. 틱은 화면 갱신에만 쓴다.
- 단위 테스트: 틱 콜백이 불규칙하게 늦어져도(백그라운드 탭 스로틀링 시뮬레이션) 60초 타이머의 종료 시각 오차 ≤ 1 tick 주기.
- 연습 중 화면 꺼짐 방지: Screen Wake Lock API(지원 시). 해제/재획득을 visibilitychange에서 처리.

### 8.6 합성 재생과 반주 (`dsp/synth` 재사용)

- 코드 라이브러리 "들어 보기", 연습곡 "들어 보기", 귀 훈련(Q4), 스케일·리프 "들어 보기"는 **테스트 fixture 생성기와 같은 합성기**로 소리를 만든다(`AudioBuffer`로 렌더).
- 마이크 판정이 켜져 있는 동안에는 위 재생을 막는다(자기 소리를 듣는 문제). **예외는 메트로놈 클릭과 곡 반주(play-along) 두 가지**다(v1 §8.6 변경, D-054).
- **반주(play-along)**: 곡 연주 모드(§11.10)에서 켜고 끌 수 있다. 내용은 합성 베이스(마디 1·3박 근음) + 곡 패턴의 합성 스트럼이고, `AudioEngine.scheduleSamples(buffer, time)`로 그리드 시각에 정확히 예약한다(메트로놈과 같은 오디오 시계). 반주가 친 시각 목록은 판정기와 공유한다.
- **반주 중 판정 정책**(사용자 결정: 전부 판정 + 이어폰 권장):
  1. 연주 모드 시작 화면에 "이어폰(유선 권장)을 쓰고 있어요" 확인 토글을 둔다. 출력 장치 라벨별로 마지막 선택을 기억한다. 블루투스 출력이면 "지연이 커요, 유선 이어폰 권장" 경고를 덧붙인다.
  2. **이어폰 확인**: 반주가 마이크로 새지 않는다고 보고 모든 판정을 평소처럼 하고 기록한다.
  3. **스피커**: 판정은 하되 (a) 반주 이벤트 시각 + RTT ± 15 ms 구간의 onset 후보는 반주 템플릿(그 이벤트의 합성 신호 대역 에너지 모양)과 맞으면 버린다(§10.4 클릭 마스킹과 같은 방식, 저역 에너지가 반주 예측보다 크게 늘면 사용자 스트럼으로 유지), (b) 코드 정확도 판정(Mode B·C)은 화면에 "참고"로 표시하고 지표·진급에 쓰지 않는다, (c) 타이밍 판정(Mode D)은 그대로 쓴다.
  4. Attempt에 `backingAudible: boolean`(스피커로 반주를 켰으면 true)을 저장한다.
  5. iOS에서 마이크를 켜면 재생 품질이 떨어지는 문제(WebKit 311451)를 연주 모드 시작 화면 안내에 적는다.

## 9. 캘리브레이션과 튜너

### 9.1 온보딩/캘리브레이션 마법사 (처음 1회, 이후 설정에서 다시 실행)

1. **권한·장치**: 마이크 권한 요청 → 장치 선택(내장 마이크 권장) → getSettings 확인 표시. 거부 시 "마이크 없이 쓰기"(수동 카운트·자가 판정 모드)로 계속할 수 있다.
2. **환경 점검(2초 무음)**: bin별 noise floor(median)와 전체 dBFS. noise RMS > −45 dBFS(설계값)이면 "주변이 시끄러워요" 경고와 함께 계속 가능.
3. **튜닝**: 6줄 순서대로 튜너(§9.2). |δ| ≤ 15 cents면 통과하고 δ를 저장(검증 기대 주파수에 반영), 아니면 조율을 안내한다. 측정 주파수로 sample-rate sanity check(기대 대비 ±1% 밖이면 경고·진단 기록).
4. **줄별 템플릿**: 개방현을 하나씩 3회 튕긴다 → 줄별 harmonic 상대 크기(h=1..8)와 정상 decay 비율(`RMS[+250..350ms]/RMS[+30..80ms]`) 저장. Mode A 뮤트 판정의 기준이 된다.
5. **지연(RTT)**: 기본은 스피커 loopback(§10.8). 실패하거나 출력 장치가 Bluetooth로 보이면 "클릭에 맞춰 8번 치기" 보정으로 전환. 결과는 (입력 장치, 출력 장치 라벨)별로 저장.
6. 결과 `Calibration`을 저장하고 요약(노이즈, 튜닝, RTT, 경고)을 보여 준다.

```ts
interface Calibration {
  id: string; createdAt: number; inputDeviceLabel: string; outputDeviceLabel: string;
  sampleRate: number; trackSettings: Record<string, unknown>;
  noiseFloorDbfs: number; noiseThirdOctaveDb?: number[]; // 1/3옥타브 요약 (JSON 직렬화 가능)
  tuningCents: number[];           // 6
  stringTemplates: { harmonics: number[]; decayRatio: number }[]; // 6
  rttMs: number; rttMethod: 'loopback' | 'tap'; rttMadMs: number;
}
```

- 사용자가 튜너 화면을 열어 둔 동안 마이크 판정 기능은 쓰지 않는다.

## 10. DSP 명세

근거: 리서치 02 §2, §7, §8. 모든 모듈은 `src/dsp/`의 순수 TS이며 Node에서 테스트된다.

### 10.1 공통 규약

```ts
type StringStatus = 'OK' | 'MUTED' | 'WRONG_NOTE' | 'UNEXPECTED' | 'WEAK' | 'UNVERIFIABLE' | 'NOT_PLAYED';
type Verdict = 'PASS' | 'FAIL' | 'RETRY';
type RetryReason = 'LOW_LEVEL' | 'CLIPPING' | 'NOISY' | 'AMBIGUOUS' | 'NO_ONSET' | 'MULTIPLE_ONSETS' | 'DETUNED';
interface DspResultBase { detectorVersion: string; confidence: number /*0..1*/; reasons: RetryReason[]; processingMs: number }
```
- `detectorVersion`은 `src/dsp/version.ts`의 semver 문자열. 알고리즘·파라미터가 바뀌면 올린다. 모든 Attempt에 저장된다(나중에 재해석 가능).
- 모든 판정은 **onset 직전 noise 대비 SNR**로 한다(절대 레벨 사용 금지).
- 클리핑이 있으면 판정하지 않고 RETRY(CLIPPING).
- **확신이 없으면 RETRY**. FAIL은 확신이 있을 때만 낸다. 엄격도 설정(관대/보통/엄격, 기본 관대)은 PRESENT/ABSENT 임계값과 cents 허용폭을 바꾸지만, §14 벤치마크는 기본값(관대)으로 평가한다.

### 10.2 FFT·윈도우·스펙트럼

- 자체 radix-2 real FFT(사전 계산 twiddle, 사전 할당 버퍼). naive DFT와 비교 테스트(상대 오차 ≤ 1e-6).
- Hann window, zero-padding ×2, 피크 parabolic interpolation. `partialPeak(X, f, tolCents)`.

### 10.3 피치 (YIN 또는 MPM)

- 직접 구현(50–100줄) 권장. 출력 `{ f0, clarity }`. 기대 f0를 아는 경우 탐색 범위를 `[f0/1.5, f0·1.5]`로 제한한다(옥타브 오류 방지).

### 10.4 Onset (Mode D와 Mode C의 기반)

- log-compressed spectral flux: `SF[n] = Σ_k max(0, log(1+γ|X_n[k]|) − log(1+γ|X_{n−1}[k]|))`, γ = 100, N = 2048, hop ≈ 5.3 ms.
- SuperFlux식 주파수 방향 max-filter(폭 3 bin)로 지속음 위 미세 변동 오탐 억제.
- 적응형 threshold: 최근 W(≈ 100 ms) 구간 median + δ, local max, 최소 간격 60 ms.
- **broadband 조건**: onset 후보 시점에 2 kHz 이상 대역 에너지가 직전 대비 급증해야 한다(피크/손톱 attack). 지속 코드를 여러 스트럼으로 오인하는 문제의 핵심 방어.
- 스트럼 그룹화: 첫 onset 이후 60 ms 안의 onset은 하나의 스트럼 이벤트로 묶고, 이벤트 시각은 첫 onset.
- 메트로놈 클릭 마스킹: `예약 시각 + RTT ± 10 ms` 구간의 onset 후보는, 에너지 증가가 클릭 대역(2–4 kHz)에 몰려 클릭 템플릿과 일치할 때만 버린다. 저역(< 1 kHz) 에너지도 함께 늘면 박자에 정확히 맞춘 스트럼이므로 유지한다(정박 스트럼을 버리는 것 금지).
- 시각 정밀화: ODF 피크 parabolic interpolation.

### 10.5 Mode A — 한 줄씩 튕기기 검증 (`verifyPluck`) · v1 핵심

입력: onset 주변 샘플, 기대 줄 `idx`와 기대 f0, calibration(템플릿, δ). 절차:
1. onset 후 `[+30, +130 ms]`에서 피치(N = 2048, hop 512), 탐색 범위 제한.
2. `cents = 1200·log2(f_meas / f0)`. |cents| ≤ 35 → 음 맞음. 그 밖 → `WRONG_NOTE`(측정 반음 차이를 결과에 포함). ±1200 근처는 옥타브 함정 — 탐색 제한으로 막고, 그래도 나오면 RETRY(AMBIGUOUS).
3. clarity < 0.85 또는 RMS < noise + 10 dB(초기값, dev 튜닝) → `WEAK` (RETRY 성격, 점수 제외).
4. decay 비율 `RMS[+250..350]/RMS[+30..80]`이 그 줄 calibration 기준 대비 크게 낮으면(기본: 기준의 0.25배 미만, dev split에서 튜닝) `MUTED`. calibration이 없으면 dev split에서 정한 전역 기본값을 쓴다.
5. 결과: `{ status, f0, cents, clarity, decayRatio, confidence }`.

x 줄 차례: 기본은 건너뛴다. 옵션 "x 줄도 쳐서 소리가 안 나는지 확인"이 켜져 있으면, 그 줄을 쳤을 때 기대 밖 음이 울리면 `UNEXPECTED`.

### 10.6 Mode B — 스트럼 검증 (`verifyStrum`) · 베타 라벨

입력: 스트럼 이벤트 샘플, 보이싱, partial 충돌 맵(§6.3), calibration.
1. 관측 window: onset 후 `[+40, +210 ms]`(N = 8192 @48k에 해당), Hann, zero-pad ×2. noise spectrum = onset 직전 0.5 s의 bin별 median.
2. 줄별 salience: 독립 partial만 써서 Klapuri식 harmonic summation(가중치 `h^-0.5`, f0 < 120 Hz는 h=1 가중치 ×0.5, tol ±30 cents, B = 5e-5) → 가중 평균 harmonic SNR(dB).
3. 판정: verifiable이 아니면 `UNVERIFIABLE`. salience ≥ T_PRESENT(초기 12 dB) → `OK`, ≤ T_ABSENT(초기 4 dB) → `MUTED`, 사이 → 불확실.
4. 기대 밖 음 탐지: 기대 partial을 모두 제외한 스펙트럼에서 상위 피크를 MIDI 후보(E2–E6)로 harmonic sum → salience가 임계값(dev 튜닝)을 넘으면 `UNEXPECTED(note, 추정 줄)`. x 줄의 개방현 음(예: C 코드에서 6번 줄 E2)은 명시적으로 검사한다(3·5배음 위주).
5. 코드 판정: 모든 verifiable 줄 OK + UNEXPECTED 없음 → PASS(UNVERIFIABLE 줄은 "확인 불가"로 표시). verifiable 줄 하나라도 확실히 MUTED 또는 확실한 UNEXPECTED → FAIL(줄 지목). 그 밖 → RETRY.
6. 같은 RETRY가 2번 연속이면 UI가 Mode A(한 줄씩)로 유도한다.

### 10.7 Mode C — 닫힌 집합 코드 분류 (`classifyPair`, `classifySet`)

- 1분 체인지는 두 후보 중 하나를 고르는 문제다. 스트럼 이벤트마다 각 후보 보이싱의 **기대 partial 전체**에 대한 log-salience 점수(또는 chroma cosine)를 계산하고 `margin = score_A − score_B`(정규화)를 낸다.
- |margin| < m_min(dev 튜닝)이면 "보류"(카운트 안 함).
- 카운트 상태 머신: 현재 코드 상태에서 **확신 있는 다른 코드 분류**가 나오면 +1 하고 상태 전환. 같은 코드 반복 스트럼·보류·열린 줄만 친 스트럼은 무시. 체인지 간 최소 간격 300 ms. **과소 집계 쪽으로 치우치게**(과대 집계가 신뢰를 더 해친다).
- `classifySet`: 해금된 코드 집합(최대 9개)에서 top-1과 margin. 코드 기억 퀴즈(Q2)가 쓴다.

### 10.8 Mode D — 타이밍 (`analyzeTiming`)과 RTT (`estimateRtt`)

- 앱이 사용자에게 보여 주는 **연주 타이밍 오차** = 스트럼 이벤트 시각 − (예약 그리드 시각 + RTT). 가장 가까운 기대 슬롯에 매칭(탐욕 매칭 + 창 제한). 이 값에는 사람의 흔들림이 들어 있는 것이 정상이다(그것을 재는 것이 목적). **검출기 정확도**(§14.3 벤치마크)는 이와 다르다: 검출 시각을 합성기의 정답 스트럼 시각과 비교한다.
- 지표: hit_rate, mean_offset_ms(앞/뒤 쏠림), sd_offset_ms(일관성), 누락·추가 스트럼 수, 쉼표 슬롯의 추가 스트럼. 개인의 일정한 선행(최근 3회 이상 평균)은 보정한 hit_rate도 함께 낸다. [근거: Repp]
- 창(설계값): 60–80 BPM ±60 ms, 80–100 BPM ±50 ms, 100+ BPM ±40 ms.
- RTT loopback: 불규칙 간격 broadband click(또는 짧은 chirp) 8개 예약 → 녹음에서 matched filter(cross-correlation)로 도착 시각 → `RTT = median(t_detect − t_sched)`, MAD ≤ 2 ms면 성공. 신호가 안 들리면 **실패를 보고**(가짜 값 금지). tap 보정은 클릭 8개에 맞춰 친 onset의 median 오프셋.

### 10.9 기본 파라미터 표 (fs = 48 kHz 기준, ms/Hz로 정의해 스케일)

| 용도 | 값 |
|---|---|
| onset | N 2048, hop 256, γ 100, max-filter 3 bin, median W ≈ 100 ms, 최소 IOI 60 ms, 스트럼 그룹 60 ms |
| 스트럼 검증 | onset+40 ms부터 N 8192 Hann, zero-pad ×2, H 6(salience)/8(충돌 맵), tol ±30 cents, B 5e-5 |
| 한 줄 판정 | N 2048 피치, 범위 [f0/1.5, f0·1.5], clarity ≥ 0.85, 음 허용 ±35 cents |
| 임계값(초기) | T_PRESENT 12 dB, T_ABSENT 4 dB, WEAK = noise + 10 dB — dev split에서 튜닝 후 고정 |
| 튜너 | N 4096, 안정 판정 연속 5프레임 ±3 cents |

이 절의 수치는 모두 **초기값**이며 dev split에서 바꿀 수 있다(§6.3 충돌 맵 규칙과 §14 임계값은 예외 — 고정). 튜닝한 최종 값과 근거는 `docs/DSP.md`에 기록한다.

### 10.10 단음 시퀀스 검증 (`verifySequence`) — 스케일·크로매틱·리프·지판 음이름

입력: 기대 음 목록 `{ slotTime, midi, idx?, legatoAllowed }[]`(그리드·RTT·개인 선행 보정이 반영된 시각), BPM, onset 스트림(broadband 여부 포함), calibration δ. 절차:
1. **매칭**: 각 슬롯에 가장 가까운 onset을 창 안에서 하나 짝짓는다(탐욕, 거리순). 창 = §10.8 BPM 창과 `0.4 × 인접 슬롯 간격` 중 작은 값. 짝이 없는 슬롯은 `MISSED`, 어느 슬롯과도 짝이 안 된 onset은 `EXTRA`(이미 짝지어진 onset과 60 ms 안이면 같은 음의 이중 검출로 보고 무시).
2. **음높이**: 짝지은 onset마다 `[+30 ms, +min(130 ms, 다음 슬롯까지 − 20 ms)]` 구간에서 MPM, 탐색 범위 `[f0/1.5, f0·1.5]`. `|cents| ≤ 35` → `OK`, 그 밖 → `WRONG_NOTE`(반음 차이 포함), clarity < 0.85 → `UNCLEAR`.
3. **레가토(베타)**: `legatoAllowed` 슬롯에 onset이 없으면 슬롯 시각 기준 같은 구간의 음높이를 재서, 기대 음이 있으면 `HAMMER_OK(beta)`로 표시한다. 이 판정은 실패를 만들지 않는다(E11 전용).
4. **사이클 판정**: 사이클의 모든 슬롯이 `OK`(레가토 슬롯은 `HAMMER_OK` 또는 미판정)이고 `EXTRA`가 없으면 **무실수(flawless)**. `UNCLEAR`가 하나라도 있으면 **불확실** — 무실수로 세지 않지만 "연속 무실수" 연속 기록을 끊지도 않는다(확신 없으면 벌하지 않음). 그 밖은 **실수**(연속 기록을 0으로).
5. **멈춤**: `MISSED`가 2개 이상 연속이면 멈춤 1회.
6. 결과: `{ notes: {slot, status, cents?, onsetOffsetMs?}[], extras, flawless, uncertain, stops, hitRate, ioiCv, detectorVersion, processingMs }`.
- 마이크가 없으면 사이클마다 "무실수였어요/실수 있었어요" 자가 보고(키 1/2)로 대신하고 `source: 'self'`로 기록한다.

### 10.11 베타 판정기 (`src/dsp/beta/`) — 측정·보고만

정답 데이터가 없는 판정이다(리서치 02:223 "공개된 전용 연구를 찾지 못했다 → 실험 기능", 02:275 "v2에서 Murgul et al. 참고"). 규칙:
- 결과는 `{ value, confidence, beta: true }`이고 **PASS/FAIL/RETRY를 만들지 않는다.** 화면에는 "참고(베타)" 라벨과 함께 보여 준다. 지표(`toMetrics`)와 진급 규칙에 쓰지 않는다.
- 합성 벤치마크로 지표를 재서 보고한다(§14.8). 목표치(`thresholds.json.beta`)에 못 미쳐도 verify는 통과한다.

| 판정기 | 입력 | 방법(초기값, dev 튜닝) | 출력 |
|---|---|---|---|
| `buzz` | 한 줄 튕기기·스트럼 | 기대 partial(±30 cents)을 notch로 지운 뒤 2–8 kHz residual 에너지비 + spectral flatness + 감쇠 초반 진폭 변조. 사용자 깨끗한 소리(캘리브레이션 템플릿) 대비 상대값(02:224–225) | 버징 의심 점수 0..1, ≥ 0.6이면 "버징 의심" |
| `direction` | 스트럼 이벤트 | 0–60 ms 안 줄별 onset 순서(저음 → 고음이면 다운), 보조로 스펙트럼 무게중심 기울기(02:464) | `down` / `up` / `unknown` |
| `legato` | onset 스트림 + 음높이 | broadband 없는 저역(<1 kHz) flux 후보 + 같은 줄 음높이 변화(01:342 "자동 판정 정확도 미검증") | 해머온 이벤트 시각·음 |
| `palmMute` | 스트럼·단음 | 감쇠비 `RMS[+150..250]/RMS[+20..60]`와 스펙트럼 무게중심을 개방 스트럼 기준과 비교 | 팜뮤트 확률 |
| `dynamics` | 스트럼 이벤트들 | 이벤트별 피크 RMS(dB)를 실행 중앙값 대비로, 마디별 평균 | 마디별 `soft`/`loud`/`even`(±6 dB 기준) |

### 10.12 반주 누출 마스킹

§8.6 정책 3(a)의 구현. 반주 이벤트(베이스 음, 반주 스트럼)마다 합성 신호의 대역 에너지 모양을 템플릿으로 저장하고, 스피커 모드에서 `이벤트 시각 + RTT ± 15 ms`의 onset 후보가 템플릿과 맞으면 버린다. 사용자 스트럼과 겹치면(저역 에너지가 템플릿 예측의 +6 dB 이상) 유지한다. 합성 벤치마크로 검증한다(§14.8, `backingBleed`).

### 11.3 E1 코드 정밀 체크 (Chord Perfect 방식)

- 입력: 보이싱, 블록 시간(1–3분), 모드(한 줄씩 기본 / 스트럼 베타 / 수동).
- 흐름(블록 시간 동안 반복): ① 다이어그램 보고 **손가락 번호 순서대로** 놓기 ② (선택) 전체 스트럼 → Mode B 베타 결과 ③ 앱이 연주 줄을 저음부터 차례로 하이라이트 → 줄마다 Mode A 판정, x 줄은 건너뜀 ④ 마지막 전체 스트럼 ⑤ "손 떼고 다시" 안내 → 다음 시도.
- 줄별 인디케이터: 대기/OK/MUTED/WRONG_NOTE/UNEXPECTED/WEAK/확인 불가를 **아이콘+색+텍스트**로. 줄이 판정되면 해당 줄 위에 코칭 힌트(§6.7).
- "귀 먼저" 옵션: 사용자가 먼저 줄별 자가 판정(울림/막힘)을 누르고 나서 앱 판정이 공개된다. 자가-앱 일치율을 지표로 기록.
- 수동 모드(마이크 없음/거부): 줄마다 "깨끗/막힘/버징" 버튼(또는 키 1/2/3).
- 결과: `{ voicingId, mode, attempts: { perString: {idx, status, cents?, confidence}[], clean: boolean, selfReport? }[], cleanRatio }`.
- **v1.1 추가**: E1 화면에서 모드(한 줄씩/스트럼 베타/수동)와 "귀 먼저"를 키보드로 바꿀 수 있다(세션 러너 안에서도, §12.3). 결과 요약에 **줄별 경향**을 보여 준다: 시도 중 같은 줄이 2회 이상 MUTED·WRONG_NOTE면 "2번 줄이 3번 중 2번 막힘 → 검지가 2번 줄에 닿는 경향"처럼 줄·횟수·코칭 힌트(§6.7)를 묶어 표시(리서치 03:95). 베타 "버징 의심"은 줄 인디케이터에 작은 참고 표시로만.

### 11.4 E2 1분 코드 체인지

- 입력: 방향 있는 쌍(A→B), 60초(설정 30–120), 카운트 방식(자동/탭/수동 입력).
- 흐름: "준비" 상태에서 A를 잡고 대기 → **첫 스트럼(onset)으로 타이머 자동 시작**(Space로도 시작) → B에 도착해 1회 스트럼, A로 돌아와 1회 스트럼 … → 60초 종료음.
- 카운트: 다른 코드에 **도착할 때마다 1**(첫 A 스트럼은 세지 않음). 자동 모드는 Mode C 상태 머신. 진행 중 `↑`/`+`/페달 = +1, `↓`/`-` = −1 보정. 탭 모드는 Enter/페달 누를 때마다 +1.

- **레퍼토리 블록**(Stage 7+, 300초, 01:265): due 곡(없으면 가장 오래 안 한 레퍼토리 곡, 레퍼토리가 비었으면 그 스테이지 이하에서 가장 최근에 연습한 곡)을 연주 단계로(암기한 곡은 숨김 단계로) 차례로 친다. 블록 시간 동안 반복.

- 범위 `scope`: `open`(개방현 6, v1), `openPosition`(0–3프렛의 자연음, 모든 줄), `strings65`(6·5번 줄 0–12프렛 자연음 16개).
- 문제 방향 둘: 위치 → 음이름 고르기(4지선다), 음이름 → 그 위치를 튕기기(튜너 음높이로 확인, 줄은 판정하지 않는다 — 같은 음 다른 줄도 정답, §3.2).
- 음 카드(위치마다 1장)의 간격 반복은 §7.5.
- 범위 졸업(01:353) = 20문항 실행에서 정답률 ≥ 90% & 응답 중앙값 < 3초. `strings65` 졸업이 Stage 10 진급 기준이다.

### 11.16 E11 해머온 손가락 운동 (01:340–343, 117)

- 입력: 손가락 쌍(1-2, 1-3, 1-4, 2-3, 2-4, 3-4), BPM(시작 60, 상한 80).
- 절차(01:117 Finger Gym을 고정): 6번 줄 5프렛부터. 한 박에 8분음표 2개 — 앞은 손가락 a로 누르고 피킹, 뒤는 손가락 b로 해머온(피킹 없음). 줄마다 4박, 6→1번 줄.
- 채점: 피킹음은 §10.10(하드), 해머온음은 레가토 베타(§10.10-3, §10.11). 끝난 뒤 "간격이 고르게 들렸나요" 자가 평가(1–3).
- 규칙: 하루 5분 권장, 10분 상한(01:343, 같은 날 누적이 10분을 넘으면 루틴에서 빼고 단독 실행도 막는다). 어려운 조합 우선 = 최근 자가 평가가 가장 낮은 쌍.
- 사다리: 피킹음 hit_rate ≥ 90% & 자가 평가 3 → +5 BPM(80까지). 진급 기준은 없다(01 표에도 없음).

### 11.17 E12 새끼손가락 운동 (01:345–347, 116)

- 절차: 6번 줄 7프렛 3번 손가락 + 8프렛 4번 손가락 → 1번 줄까지 → 4→3 순서로 복귀 → 2-4, 1-4 조합 반복. 블록 2분.
- 채점: 완료 체크 + 음 명료도 자가 보고(1–3). 속도 채점 없음("NOT a speed drill").
- 안전: "늘어나는 느낌까지만, 아프면 멈추세요", "3번 손가락이 대신 힘을 쓰면 쉬어 가세요"(01:161, 384)를 상시 표시. 통증 ≥5 다음 날은 빼고(§7.3-7), 끝난 뒤 통증 0–10을 묻는다(E7과 같은 방식).

### 11.18 E16 프렛 위치 비교 (01:238 "프렛 위치 압력 비교 테스트", 01:94)

- 목적: "프렛 바로 뒤를 누르면 적은 힘으로도 깨끗하다"를 직접 들어 보게 한다.
- 절차: 2번 줄 1프렛(C4)을 같은 가벼운 힘으로 세 위치에서 2번씩 튕긴다. ① 프렛 바로 뒤 ② 칸 가운데 ③ 프렛 쇠 위(너무 넘어감). 화면이 위치를 그림으로 보여 준다.
- 판정: 매 튕김을 Mode A로(OK / WEAK / MUTED / WRONG_NOTE), 위치별 결과와 clarity·감쇠비를 나란히 보여 준다. 마이크가 없으면 "깨끗/막힘/버징" 자가 판정.
- 결과: `{ positions: { pos, statuses[], clarity?, decayRatio? }[] }`. 통과·실패 개념은 없다(완료 1회 이상이 Stage 0 루틴 보장 대상).

### 11.19 E17 단음 리프 (01:240, 242)

- 입력: 리프(§6.9), BPM(리프 기본 템포부터), TAB 보이기/숨기기.
- 채점: 리프 1회 = 한 사이클, §10.10. 사다리: 4회 연속 무실수 → +5 BPM(목표 = 리프 기본 템포 + 20, 설계값). −5 규칙은 E10과 같다.
- R4는 팜뮤트 지시가 붙는다(판정은 `palmMute` 베타).

### 11.20 Q5 TAB 읽기 퀴즈 (01:242 "TAB 읽기")

- 문제: TAB 한 칸(줄·프렛)을 보여 주고 지판 위치를 3지선다로, 또는 지판 위치를 보여 주고 맞는 TAB을 3지선다로. 10문항, 정답률. TAB의 위쪽 선이 1번 줄이라는 점을 첫 문항 전에 안내한다.

### 11.21 Q4 귀 훈련 확장 (01:355–357)

- 종류 `kind`: `majmin`(v1), `interval`(위로 올라가는 두 음: 장2도, 단3도, 장3도, 완전4도, 완전5도, 옥타브 — 6지선다, 설계값), `progression`(I에서 시작한 두 번째 코드가 IV인지 V인지 다시 I인지 — 3지선다, 키 G·C·D·A·E 무작위).

## 13. 데이터

### 13.1 원칙

1. **콘텐츠(정의)와 기록(사실)을 분리**: 보이싱·커리큘럼·연습곡은 번들 시드(읽기 전용) + 사용자 커스텀. 세션·시도는 사용자 데이터.
2. **Attempt는 append-only**: 파라미터 스냅샷, `detectorVersion`, 자동 값·보정 값·자가 보고를 함께 저장. 수정·삭제 API를 만들지 않는다(데이터 초기화만 예외).
3. **지표(MetricSample)와 스킬 상태(SkillState)는 Attempt에서 언제든 재계산 가능한 캐시**다. `rebuildDerived()`를 제공하고, "재계산 결과 = 증분 갱신 결과"를 테스트한다.
4. `subjectKey`로 지표를 묶는다(`chord:C`, `pair:A|D`, `pairdir:A>D`, `strum:P3`, `song:s01` ...).

### 13.2 Dexie 스키마 (v2)

v1 스키마(v1 SPEC §13.2)를 유지하고 버전 2에서 다음을 더한다. 인덱스가 바뀌는 테이블만 `db.version(2).stores(...)`로 다시 선언하고, `upgrade`에서 기존 행을 옮긴다.

```ts
db.version(2).stores({
  reviews: 'subjectKey, due, kind',                 // kind: 'chord'|'pair'|'pattern'|'song'|'scale'|'riff'|'card'
  sessions: 'id, startedAt, splitOf',               // 30분 세션 분할(§7.3-11)
}).upgrade(tx => { /* reviews.kind 채우기, progression 필드 이동 */ });
```

- `progression`: `gVoicing: 'G-2f'|'G-3f'|'G-4f'`, `completedBeginner1`, `completedBeginner2`, `beginner2CompletedAt?`, `prescriptions: { kind, subjectKey, startedSession, expiresAfterSessions, reason }[]`(v1 `prescribedDrills` 대체), `selfChecks: Record<itemId, 'done'|'notYet'>`.
- `skills.metrics`: 사다리 subject마다 `currentBpm`, 곡마다 `songStage`, 카드마다 간격 단계.
- `attempts.result`: 연습별 결과 스키마(§11) + `backingAudible?`, `beta?: Record<string, unknown>`(베타 판정 값, 지표로 쓰지 않음).
- `meta.settings`: 블록 전환 화면, 헤드 모양, 반주 볼륨, F-small 대체, 출력 장치별 이어폰 확인 기억.
- 내보내기 `schemaVersion: 2`, v1 파일 가져오기는 마이그레이션(1→2)을 거친다. 왕복 테스트와 "v1 내보내기 파일 → v2 가져오기" 테스트를 둔다.

### 13.3 내보내기/가져오기

- `exportAll()` → `{ app: 'guitar-hero', schemaVersion, exportedAt, tables: {...} }` JSON 파일 다운로드(파일명에 날짜). 녹음 오디오는 포함하지 않는다(별도 내보내기).
- `importAll(file)`: zod로 검증 → schemaVersion 마이그레이션 → **미리보기(테이블별 건수) 후 확인** → 병합(같은 id는 건너뜀) 또는 교체(2단계 확인).
- 왕복 테스트: 임의 데이터 생성 → export → 빈 DB에 import → 모든 테이블 deep-equal.
- 시작 시 `navigator.storage.persist()` 요청. 마지막 백업 후 7일이 지나면 홈에 리마인더. iPad/iPhone에서는 홈 화면 추가(PWA)를 안내한다(Safari 저장소 정책).

### 13.4 녹음 키트 (실측 fixture)

- 설정 > 녹음 키트: 안내된 순서로 라벨 붙은 클립을 녹음한다. 예: 코드별 {깨끗한 스트럼, 한 줄씩 튕기기, 특정 줄 일부러 뮤트, x 줄 울림}, 1분 체인지 30초(사용자가 직접 센 횟수 입력), 메트로놈에 맞춘 스트럼 8마디(RTT 함께 기록).
- 오디오는 OPFS에 16-bit PCM WAV로 저장, 메타는 Dexie. 내보내기: WAV 파일들 + `labels.json`(보이싱, 라벨, 기대 결과, 기기, sampleRate, calibration 요약)을 하나씩 다운로드하거나 zip(의존성 없이 store 방식 zip 직접 구현 또는 permissive 라이브러리).
- 사용자가 내보낸 파일을 `tests/fixtures/real/<기기명>/`에 넣으면 `npm run bench:real`이 Mode A/B/C/D를 돌려 리포트한다(파일 없으면 "no fixtures"로 성공).
- 녹음 키트 클립에 스케일 1단계 1사이클, 리프 1개, 해머온 4박을 더한다(실측 fixture로 §10.10 확인용).

- 무결성 테스트: v1 파일의 **모든 키 경로가 v1.1 파일에 같은 값으로 있다**(`version`·`$comment` 제외, 배열은 v1 원소를 모두 포함하는 상위 집합이면 됨). 즉 v1.1은 v1 임계값을 하나도 완화하지 않는다.

### 14.1 테스트 피라미드

1. **순수 단위 테스트(Vitest, Node)**: `domain/`, `dsp/`, 데이터 변환, 러너(가짜 clock), 메트로놈 스케줄러, 타이머, 루틴 생성, 진급 엔진, 코칭 규칙, export/import.
2. **합성 벤치마크(§14.3)**: 정답이 확실한 합성 신호로 DSP 판정기의 경계 조건을 체계적으로 시험.
3. **실녹음 벤치마크(§14.4)**: GuitarSet(CC BY 4.0, 어쿠스틱, 줄별 주석).
4. **실측 fixture(`bench:real`)**: 사용자가 녹음 키트로 추가(goal 범위에서는 하네스만, 데이터는 사후).
5. **E2E(Playwright, §14.5)**: 가짜 마이크로 전체 흐름.
6. **무결성 테스트(§14.6)**: 규칙 위반 자동 탐지.

### 14.2 합성기 (`src/dsp/synth/`, 테스트·앱 공용)

- **확장 Karplus-Strong**: 분수 지연 allpass 보정, 손실 필터(sustain/뮤트), 초기 excitation lowpass(밝기), pick position comb, 선택적 buzz(soft-clip + 짧은 noise burst — v1 판정 대상은 아니지만 생성은 가능).
- **Additive**: `f_h = h·f0·sqrt(1 + B·h²)`, partial별 지수 decay, 몸통 공진을 흉내 낸 고정 EQ 몇 개.
- **스트럼**: 줄별 신호를 다운(6→1)/업(1→6) 순서 지연(0–40 ms)으로 합성, 줄별 gain jitter.
- **채널 모델**: 마이크 HPF(2차, 0/100/150 Hz), 선택 LPF 8 kHz, 잡음(white/pink, 지정 SNR), 작은 방 잔향(지수 감쇠 noise IR, RT60 ≈ 0.3 s), 메트로놈 클릭 누출(예약 시각 + RTT, 상대 −20 dB).
- **난수**: 시드 PRNG(mulberry32 등)만 사용. `Math.random` 금지(`dsp/`, `tools/`).
- WAV writer/reader(16-bit PCM, 32-bit float)를 포함한다.
- **v1.1 합성기 확장**:
  - **단음 시퀀스**: 기대 음 목록(줄·프렛·슬롯 시각)대로 단음을 이어 렌더한다. 이전 음은 다음 음 시작 시 줄이 같으면 끊고(같은 줄 재피킹), 다르면 자연 감쇠.
  - **레가토(해머온)**: 피크 노이즈 없이, 이전 음의 줄 진동을 이어받아 주파수만 바꾼다(KS 지연 길이 전환 + 짧은 크로스페이드, attack 2–8 kHz 에너지가 피킹의 −20 dB 이하).
  - **스윙**: 슬롯 생성에 스윙 비율 r.
  - **반주 누출**: §8.6의 반주(베이스 + 스트럼)를 렌더해 RTT 지연 후 상대 레벨(−25…−10 dB)로 마이크 채널에 섞는다.
  - **버징(베타용)**: KS 루프의 줄-프렛 접촉 비선형(soft clip) + 짧은 고역 noise burst, 세기 `buzz ∈ [0, 1]`(02:367).
  - **팜뮤트(베타용)**: 감쇠 시간 0.1–0.3 s, 4 kHz 이상 −12 dB 셸빙.
  - **셈여림(베타용)**: 스트럼 이득을 마디 단위로 ±(6–12) dB.

### 14.3 합성 벤치마크 (`bench:dsp:dev`, `bench:dsp`)

**Split**: dev 시드 1000–1999(튜닝용, 마음대로 반복), test 시드 9000–9999(마일스톤 종료와 최종 검증에서만). 두 split은 같은 생성기·같은 매트릭스, 다른 시드.

**매트릭스 최소 차원**(`thresholds.json.matrix`): sampleRate {44100, 48000} × 합성 모델 {KS, additive(B ∈ [1e-5, 1.5e-4])} × SNR {15, 25, 40} dB × 마이크 HPF {0, 100, 150} Hz × 잔향 {없음, 작은 방}, 줄 gain jitter ±6 dB, 줄별 detune ±15 cents(판정기에는 잔차 ±3 cents의 calibration δ 제공), 스트럼 퍼짐 0–40 ms. 보이싱: Stage 0–7 전부 + F-small, C7, B7, G5. 조합이 너무 많으면 각 차원 값이 고르게 나오도록 층화 표본추출(stratified sampling)하되, **최소 표본 수**(`minimumTestSizes`)를 지킨다.

**지표 정의 (고정 — 해석 여지 없음)**:
1. **매트릭스 값의 의미**: `sampleRates`, `synthModels`, `snrDb`, `micHighpassHz`, `reverb`, `voicings`, `*Conditions`는 **집합**이다(모든 원소가 test split에 나와야 한다). 그 밖의 길이 2 숫자 배열(`additiveInharmonicityB`, `strumSpreadMs`, `changesPerMin`, `bpm`, `humanMeanOffsetMs`, `rttMs`, `latencyMs`)은 **[min, max] 연속 구간**이고 균등 추출한다(B는 로그 균등). 무결성 테스트는 구간마다 양 끝 10% 안의 표본이 각각 존재함을 확인한다.
2. **SNR** = 신호 RMS(onset 후 0–500 ms, 모든 줄 합) ÷ 정상 잡음 RMS(dB). **작은 방 잔향** = 지수 감쇠 noise IR, RT60 0.3 s, DRR +3 dB.
3. **뮤트 줄 모델**: Mode A/B/C 모두 `modeAMutedDecayDbIn120ms`(120 ms 안에 −30 dB)를 쓴다. 줄을 빼는 방식으로 뮤트를 흉내 내지 않는다. **x 줄 울림** = 그 줄의 개방현을 정상 sustain으로 합성. 합성기 자체 테스트: 생성음의 f0와 명목 f0 차이 ≤ 0.5 cent(KS 분수 지연 보정 검증).
4. **표본 추출**: 조건 안의 대상(뮤트할 줄, 틀릴 줄, 쌍, 보이싱)은 후보 중 시드 균등 추출한다. 쌍은 §6.5의 25쌍 × G 보이싱 2종(G-2f, G-3f) 중 균등. 조건별 최소 표본 = `minimumTestSizes[mode]` ÷ 조건 수(올림).
5. **불가능한 조합 제외**: `x-string-ringing`은 x 줄이 있는 보이싱만, 그리고 그 줄을 울린 보이싱에 §6.3 규칙을 적용했을 때 그 줄이 verifiable인 경우만. `verifiable-muted`·`wrong-fret-verifiable`은 verifiable 줄이 있는 보이싱만, `dependent-muted`는 비verifiable 줄이 있는 보이싱만. 같은 음을 다른 줄에서 내는 경우(예: G5에서 개방 3번 줄 G3 = 4번 줄 5프렛 G3)는 v1 범위 밖이라 제외. 제외한 조합 수를 리포트한다.
6. **분모**: false reject = 정상 조건 표본 중 확정 부정 판정(MUTED·WRONG_NOTE·UNEXPECTED·FAIL)의 비율. RETRY 비율 = RETRY/WEAK 판정 비율. false accept = 결함 조건 표본 중 OK/PASS 비율. 검출률 = 결함 조건 표본 중 그 결함을 정확히 판정한 비율(Mode A 뮤트 → MUTED, 잘못된 음 → WRONG_NOTE이면서 반음 차이 일치).
7. **Mode B 층**: `modeB.cleanFailMax`는 모든 SNR 층에서, 나머지 Mode B 지표는 `modeB.detectionStrataSnrDbMin`(25 dB) 이상 층에서 판정한다. SNR 15 층의 나머지 값은 보고만 한다(베타 기능, 조용한 방 전제).
8. **Mode C 정답**: 다른 코드에 도착해서 친 스트럼마다 1(그 스트럼에 뮤트 줄이 있어도 1). 같은 코드 추가 스트럼, 개방현 스트럼, 시작 코드의 첫 스트럼은 0. `classifySet`은 Stage 0–7의 8코드(G 두 보이싱은 같은 클래스) 중 깨끗한 스트럼의 top-1, SNR ≥ 25 층.
9. **Mode D 정답**: 검출기 타이밍 오차 = 검출 스트럼 시각 − **합성기의 정답 스트럼 시각**(그 스트럼 첫 줄 onset, 녹음 시간축). 사람 지터·평균 선행은 정답에 이미 들어 있으므로 오차가 아니다. 판정기에는 실제 RTT + U(−2, +2) ms를 준다. F1 정답 = 합성한 모든 스트럼. 누락·추가 정답 = 정답 시각에 §10.8 창 규칙을 적용한 슬롯 판정이고, 판정기의 슬롯 판정과 비교한다. F1 시퀀스의 50%에는 클릭 누출을 넣는다.
10. **튜너 정답** = 명목 기본음(h=1) f0. 튜너 지표는 SNR 25·40 층(`tuner.snrDbMin` 20 이상)에서 판정한다.
11. **test split이 마일스톤 종료 때 실패하면**: DECISIONS에 기록 → 같은 조건 분해로 dev split에서 재현·수정 → test 재실행. 모든 test 실행(시각, detectorVersion, 결과)을 `docs/BENCHMARK.md`의 "test-run log"에 남긴다.
12. **v1.1 매트릭스 확장**: `matrix.voicings`에 Stage 8–11 보이싱(G-4f, Cadd9, Dsus4, A7sus4, Em7, Fmaj7, F, C5, E5, A5, D5, F5, A7, D7, E7, G7)을 더한다. 기존 Mode A·B 임계값을 그대로 적용한다. Mode C(`classifyPair`) 쌍 표본은 §6.5의 모든 쌍(핵심 25 + Stage 8–11 25쌍) × G 보이싱 3종 중 균등(§14.3-4의 "25쌍 × G 2종" 문장을 대체한다). `classifySet`은 v1 정의(Stage 0–7 8코드, `modeCSet`)를 그대로 두고, Stage 8–11은 §14.8의 `modeCSetStage8to11`로 따로 판정한다.
13. **집합 키 추가**(§14.3-1의 집합/구간 구분): `sequence.shapes`, `sequence.scaleSteps`, `sequence.noteValues`, `sequence.conditions`, `swing.patterns`, `betaConditions.directions`, `modeCSetStage8to11.sets`, `gVoicings`는 **집합**이다. `sequence.bpm`, `sequence.rttMs`, `swing.swingRatio`, `swing.bpm`, `backingBleed.relDb`, `betaConditions.buzzStrength`, `betaConditions.palmMuteDecayS`, `betaConditions.dynamicsDeltaDb`는 **[min, max] 구간**이다.

### 14.4 GuitarSet 실녹음 벤치마크 (`bench:guitarset`)

- 데이터: Zenodo record **3371780**(GuitarSet 1.1.0, **CC BY 4.0**)의 `audio_mono-mic.zip`(≈657 MB)과 `annotation.zip`(≈39 MB)만 받는다. Zenodo API의 체크섬으로 검증한다. 위치: `data/guitarset/`(gitignore). 레포에는 다운로드 스크립트와 출처 표기만 커밋한다.
- 다운로드 실패 처리: 지수 백오프로 최대 3회. 3회 모두 실패하면 다운로드 스크립트가 `data/guitarset/.download-blocked`에 **시도별 URL, HTTP 상태 또는 curl exit code, 시각**을 JSON으로 기록하고 벤치마크는 **BLOCKED**를 반환한다. 마커는 다운로드 스크립트만 쓴다(손으로 만들지 않는다). verify는 마커 내용을 출력하고, 이 마커가 있을 때만 BLOCKED를 허용한다. 마커 없이 데이터가 없으면 FAIL이다.
- 클립 구분: 파일명에 `_comp`가 있으면 comp, `_solo`가 있으면 solo. 장르는 파일명 `<player>_<장르><n>-...`의 장르 코드(BN, Funk, Jazz, Rock, SS).
- JAMS 파싱: 줄별 `note_midi` 주석(data_source 0–5 = 6번→1번 줄)에서 이벤트를 만든다.
  - **스트럼 이벤트**(comp 클립): 60 ms 안에 시작하는 노트 ≥ 3개를 묶는다. 필터: 울리는 줄 ≥ 4, 모든 노트 지속 ≥ 250 ms, 이후 300 ms 안에 다른 onset 없음. 기대 보이싱 = 이벤트에서 울린 줄별 MIDI(나머지 줄은 x).
  - **단음 이벤트**(solo 클립): 주석 지속 ≥ 400 ms, 다음 노트 onset까지 ≥ 400 ms, 앞 150 ms 안에 다른 노트 없음. 노트 구간의 `pitch_contour` 편차가 ±35 cents를 넘는 노트(벤딩·슬라이드·비브라토)는 제외. (Mode A decay window가 +350 ms까지이므로 그보다 짧은 노트는 쓰지 않는다.)

**sequence 정의**:
- 조건 매트릭스(`matrix.sequence`):
  - 모양: 스케일 3종의 1–5단계, 크로매틱, 리프 4개
  - BPM 60–100, 음가 4분·8분
  - sampleRate·모델·SNR·HPF·잔향은 공통 매트릭스
  - 조건 {clean, wrong+1, wrong-1, missed, extra}

  - extra: 인접 두 슬롯의 중간 시각 ± U(−10, +10) ms에, 모양 안의 다른 음 1개를 직전 음과 다른 줄에서 넣는다.
  - wrong±1: 무작위 1음을 같은 줄 프렛 ±1로 바꾼다(개방현이면 +1만).
- 정답:
  - 음 onset 정답 = 합성기의 음 시작 시각(녹음 시간축), 음 정답 = 합성한 MIDI.
  - note onset F1의 검출 집합 = 그룹화 후 onset 스트림이고, ±30 ms 일대일 탐욕 매칭한다.
- 분모:
  - 음 OK 비율 = clean 사이클의 모든 슬롯(MISSED·UNCLEAR는 OK 아님).
  - 무실수 판정 비율 = clean 사이클 중 음 수 ≤ `matrix.sequence.flawlessGateMaxCycleNotes`(24)이고 SNR ≥ `synthetic.sequence.flawlessGateSnrDbMin`(25 dB)인 것(그 밖 사이클은 보고만 — Mode B 층 규칙과 같은 방식).
  - 불확실 비율 = SNR ≥ 25 dB 층의 모든 clean 사이클(SNR 15 층은 보고만).
  - missed 검출 = 생략 슬롯이 MISSED인 비율. extra 검출 = 추가 음 시각 ±30 ms 안에 EXTRA가 있는 비율.
  - 결함 사이클 무실수 오판 = 결함 사이클 전부.
- 시퀀스 SNR = 각 음 [0, min(500 ms, IOI)] 구간 RMS의 평균 ÷ 정상 잡음 RMS.
- 판정기에는 그리드·RTT(+U(−2, +2) ms)·δ를 준다.

**swing 정의**: 판정기에는 합성에 쓴 스윙 비율 r을 연습 파라미터로 준다. 슬롯 배정 정답 = 합성 슬롯 인덱스이고, 분모 = 합성한 모든 스트럼(놓친 스트럼은 오답)이다. F1·오차 정의는 v1 Mode D와 같다.

**backingBleed 정의**:
- 사용자 패턴은 P0, 반주는 베이스(마디 1·3박 근음) + P3 스트럼으로 고정한다. 반주 레벨은 사용자 스트럼 대비 −25…−10 dB이고, RTT 지연 후 섞는다.
- F1 정답은 사용자 스트럼뿐이다.
- "반주 이벤트를 스트럼으로 센 비율"의 분모 = 사용자 스트럼과 ±50 ms 안에서 겹치지 않는 반주 이벤트. 분자 = 그중 `이벤트 시각 + RTT ± 25 ms` 안에 검출 스트럼이 있는 것.

**modeCSetStage8to11 정의**: 후보 집합은 `matrix.modeCSetStage8to11.sets`(스테이지별, 근음 중복 없음)에서 고르고, 정답 보이싱은 그 집합 안에서 균등 추출한다. v1의 `modeCSet`(Stage 0–7의 8코드)은 v1 정의 그대로 유지한다.

**최소 표본**(`minimumTestSizes`): sequenceCycles 1200, swingEvents 3000, backingBleedEvents 2000, modeCSetStage8to11Strums 1000, beta 판정기마다 500.

베타 지표는 `docs/BENCHMARK.md`의 별도 절("베타 — 게이트 아님")에 값·목표치·n을 쓴다. §16.1로 미룬 기능이 있어도 고정 매트릭스(`scaleSteps`, `betaConditions` 등)의 생성기 커버리지 의무는 남는다(생성·보고는 하고 판정기만 없으면 "미구현"으로 보고).

**v1 하드 게이트 보호**: 시퀀스 경로의 onset 파라미터(레가토 후보 포함)는 스트럼 경로(v1 Mode D·GuitarSet 스트럼 F1)와 **별도 파라미터 세트**로 둔다. v1 스트럼 지표(GuitarSet test 0.877, 임계 0.85)를 떨어뜨리지 않는다.

### 14.9 커리큘럼 추적성과 루틴 시뮬레이션 (`src/domain/simulate.ts` + 테스트)

v1에서 "배울 것"이 연습으로 이어지지 않은 결함을 다시 막는 장치다. 모두 Vitest 단위 테스트이고 `npm run test`에서 돈다.

1. **구조**:
   - `simulate.ts`는 순수 모듈(§5.1)이다. 앱 계층의 함수(`pluginParamsFor`, 플러그인 `toMetrics`, 스킬·복습 갱신)는 **인자로 주입**받는다.
   - 테스트가 실제 레지스트리와 실제 함수를 주입한다. 연습 결과만 학습자 모델이 만든다.
   - 그 밖에는 앱과 같은 도메인 코드(`generateRoutine`, `evaluateStage`, `detectStagnation`, 복습 큐)를 쓴다. 시뮬레이션은 하루 1세션이고, 모든 스테이지에서 `confirmedOverCap = true`, 세션 길이 설정 = 템플릿 길이로 돈다.
2. **가상 학습자 모델**(결정적, 시드, 수치 고정):
   - `blank`: 모든 실행 결과가 0점·실패·자가 보고 "아직".
   - `improving`:
     - **1분 체인지**: 쌍(무방향)마다 첫 실행 24/분, 그 쌍 실행마다 +3(상한 45). 실행 시간은 60초.
     - **E3**: 첫 clean_rate 0.6, 실행마다 +0.1(상한 1.0), clean_changes = E2 값 × clean_rate.
     - **사다리가 있는 항목**(E5·E6·E8·E9·E10·E11·E17): 실행마다 통과. 사이클형(E9·E10·E17)은 실행 1회 = 4사이클 무실수.
     - **E1**: 코드마다 첫 clean 비율 0.3, 그 코드 실행마다 +0.1(상한 1.0). 시도 10회로 계산한다.
     - **퀴즈**: Q2는 정답, 반응 2.5초. Q1·Q3·Q5 정답률 0.95, 반응 2.0초(20문항이면 19/20). Q4는 정답률 0.9.
     - **곡**: 학습 단계 실행은 끝까지 감. 연주·숨김 단계는 멈춤 0으로 완주.
     - **기타**: K1은 3번째 등장에 "됐어요". E16·E12는 완료. E7은 통증 0.
     - **진행**: 졸업 시험은 Stage 7 최소 체류를 채운 다음 세션에 5항목 통과. 홈 제안(G 전환, 조건부 진급)은 다음 세션 시작에 수락. 항목 1개 = 실행 1회(블록 반복은 시뮬레이션하지 않는다).
   - `plateau`: `improving`과 같되 Stage 3의 Am–Em 쌍이 첫 실행부터 25/분에 고정.
   - `withReviews`: `improving`과 같되 Stage 5 진입 시 졸업 항목 30개가 같은 날 due가 되도록 시드한다. 쌍 18 = Stage 5 해금 18쌍 전부(통과 기록 포함 — 그래서 위험 쌍이 없다), 코드 7 = Stage 0–5 코드, 패턴 5 = P0–P4.
   - `pain`: `improving` + 7연습일마다 한 번 통증 6 보고.
3. **시뮬레이션 의미(고정)**:
   - **창** = 연속 7연습일.
   - **마지막 등장** = §7.3 입력의 세션 번호 정의.
   - **커버리지 실행**: Stage s 28일 실행은 진급 평가를 끄고 Stage s에 고정한다. 시작 상태는 `improving` 모델을 Stage 0부터 진행해 Stage s에 진입한 날의 스냅샷이다. `blank` 모델은 Stage 0·1에서만 단언한다. `withReviews`는 Stage 5, `plateau`는 Stage 3, `pain`은 모든 스테이지에서 단언한다.
   - **도달 실행**: Stage 0에서 시작해 진급 평가를 켜고 계속 간다.
   - **규칙 → 연습 대응표**는 테스트 안에 상수로 둔다:
     - `recallPassed` → Q2
     - `pairsPassedAtLeast`·쌍 규칙 → E2
     - `scaleStepGraduated`·`scaleMemorized` → E10
     - `songsCompletedAtLeast` → S 연주 단계
     - `quizRunAtLeast` → Q3
     - `chordCleanRatioAtLeast` → E1
     - 패턴 규칙 → E5
     - `metricAtLeast altpick` → E8
     - `examPassed`·`daysInStageAtLeast`·`sessionsInStageAtLeast`는 대응 연습이 없어 단언에서 뺀다.
   - **교착** = `evaluateStage()`의 모든 기준 충족(또는 조건부 진급 가능)이 참인 세션의 다음 세션에 진급(또는 제안)이 일어나지 않음.
4. **커버리지 단언**(Stage 0–11 각각, 위 모델별 적용 범위, 28일):
   - **learn 항목**: §7.1 learn 표의 각 항목이 practicedBy 중 하나로 7연습일 창마다 2회 이상 나온다(K1 "됐어요" 이후 제외 규칙 포함).
   - **순환 블록**: 목록의 각 항목이 3세션마다 1회 이상 나온다(편집하지 않은 기본 템플릿 기준).
   - **진급 규칙**: 규칙마다 그 지표를 만드는 연습(대응표)이 7연습일 창마다 1회 이상 나온다.
   - **필요 쌍 보장**: "현재 스테이지 진급 규칙이 요구하고 아직 통과하지 않은 쌍"이 연습일 7일 안에 배정된다.
   - **복습**(`withReviews`): kind별로 (i) 먼저 due된 항목이 먼저 배정되고(FIFO), (ii) 배정 지연 ≤ max(7, ⌈q/c⌉ + 1) 연습일이다. q = 그 kind의 동시 due 수, c = 그 kind의 일일 용량(코드 1, 쌍 1, 패턴 1/3, 곡 Stage 1–6은 1·Stage 7+는 3, 카드는 Q2·Q3 실행당 문항 수).
   - **합계**: 통증 감량·휴식일이 아닌 세션은 Σ 블록 시간 = 템플릿 길이 T다. 통증 감량 세션은 Σ = T − Σ(감량 항목의 원래 길이 − 감량 길이) − Σ(뺀 E11·E12의 원래 길이)다.
5. **도달 단언**:
   - `improving` 학습자가 Stage 0에서 시작해 스테이지마다 "최소 체류(세션·일) + 20연습일" 안에 다음 스테이지로 가고, Stage 11 기준을 채워 초급 2 수료에 이른다. 교착이 0이다.
   - `plateau` 학습자는 Stage 3 진입 후 22연습일 안에 조건부 진급 제안을 받는다. 수락 뒤 Stage 4 루틴에 처방이 추가되고, 순환 보장이 깨지지 않으며, 교착이 0이다.
   - `pain` 학습자의 통증 다음 날 E1·E2·E3 실행 파라미터 길이가 절반이고 E11·E12가 빠진다.
6. **파라미터 의미 단언**:
   - progression 모드 실행의 코드가 2개 이상이다.
   - 템포 항목의 BPM이 사다리 현재 BPM과 같다(활성 −10 처방 중이면 현재 − 10).
   - E7 시작 프렛이 `nextStretchStartFret` 결과와 같다.
   - Stage 9 c-major-open 3번째 배정부터 `tabHidden`이다.
   - Stage 10 Q3 `strings65`가 20문항이다.
   - Stage 7+ 레퍼토리 블록이 매 세션 있다.
7. **리서치 추적표**:
   - `docs/goal/v1.1/traceability.json`의 모든 항목이 `status ∈ {implemented, excluded}`를 갖는다.
   - `implemented` 항목은 v1.1 SPEC에 있는 절 번호와 PROGRESS.md AC 표에 있는 AC ID를 가리킨다. 테스트가 SPEC 제목과 PROGRESS 표를 읽어 확인한다.
   - `excluded` 항목은 빈 칸이 아닌 근거(`note`)를 갖는다.
   - 항목 수는 `minimumEntries` 이상이다.

### 16.1 수렴을 위한 축소 허용 목록 (DEFERRABLE)

§2.6의 축소 조건(M13 커밋 이후, 같은 하위 항목 때문에 마일스톤 verify가 3회 연속 실패)이 걸리면, 아래 하위 항목**만** 미룰 수 있다. 미룬 항목은 `docs/BACKLOG.md`에 `DEFERRED (턴 n, 사유)`로 적고, 해당 AC의 증거 칸에 `DONE (deferred: <항목>)`으로 표시하며, `traceability.json`의 해당 항목 대조 결과(FINAL_REPORT)에 "deferred"로 밝힌다. **이 목록 밖의 항목은 미룰 수 없다.** 미룬 연습이 진급 기준에 쓰이면 그 기준은 자가 보고 항목으로 바꾸고 시뮬레이션 대응표도 함께 바꾼다. 미룬 연습이 §7.1 learn 표의 유일한 practicedBy이면(예: Stage 4 TAB 읽기 → Q5, Stage 7 셈여림 → E5 셈여림) 그 learn 항목은 테스트 안의 "deferred" 상수 목록으로 커버리지 단언과 무결성 8에서 뺀다.
- Q4 `interval`·`progression` 종류 (AC-NE7의 일부)
- Q5 TAB 읽기 퀴즈 (AC-NE6의 일부. E17 리프는 유지)
- E5 셈여림 모드, 베타 `dynamics` 판정기 (AC-NE9·BT1의 일부)
- 베타 `legato`·`palmMute` 판정기 (AC-BT1의 일부. E11·팜뮤트 연습은 자가 평가로 유지)
- 반주의 합성 베이스 라인 (AC-BK1의 일부. 반주 스트럼과 이어폰 정책은 유지)
- E10 4·5단계 (AC-NE4의 일부. 1–3단계와 진급 기준의 1단계는 유지)
- 블록 전환 5초 화면 (AC-RT4의 일부)
- 새 E2E 시나리오의 WebKit 프로젝트 실행 (Chromium 실행은 유지)

### 16.2 마지막 순서 (M15)

1. 모든 AC가 DONE → `docs/goal/v1.1/FINAL_REPORT.md`(verify 표는 직전 verify 결과)·PROGRESS.md·README 갱신 → M15 커밋.
2. HEAD(M15 커밋)에서 `npm ci && npm run verify`를 백그라운드로 실행하고 완료를 기다린다. 실패하면 고치고 다시 커밋한 뒤 반복한다.
3. 통과하면 §18.2를 출력한다. 이 시점 이후에는 파일을 수정하거나 커밋하지 않는다(PROGRESS.md 갱신도 하지 않는다 — §2.5 예외). FINAL_REPORT의 verify 표와 최종 실행 결과가 다르면 최종 출력이 우선이고, 그 차이를 출력에 한 줄로 밝힌다.

- **Mode A**: 한 줄씩 튕겨 줄마다 확인(가장 신뢰도 높음). **Mode B**: 한 번에 긁은 소리로 확인(베타, 확인 가능한 줄만). **Mode C**: 정해진 후보 코드 중 어느 것인지 분류(1분 체인지·퀴즈). **Mode D**: 메트로놈 대비 타이밍.
- **verifiable 줄**: 스트럼 소리에서 다른 줄 배음과 겹치지 않는 partial이 2개 이상이라 단독으로 판정할 수 있는 줄(§6.3).
- **RTT**: 출력 지연 + 입력 지연. 메트로놈 대비 타이밍 보정에 이 값 하나만 필요하다.
- **dev/test split**: 파라미터를 맞추는 데이터(dev)와 최종 성적을 재는 데이터(test). test로 파라미터를 고치면 성적이 부풀려진다.
- **무실수 사이클**: 시퀀스 연습(스케일·크로매틱·리프)에서 모든 음이 제때·맞는 음높이로 울리고 추가 음이 없는 한 바퀴(§10.10).
- **사다리 현재 BPM**: 템포 사다리가 있는 연습에서 다음에 시작할 템포. 스킬 상태에 저장되고 루틴이 읽는다(§7.4).
- **베타 판정**: 정답 데이터가 없어 측정·보고만 하는 판정. PASS/FAIL을 만들지 않고 진급에 쓰지 않는다(§10.11).
- **OMC / PFC**: 1분 코드 체인지(E2) / 정확 빠른 체인지(E3). 정체하면 서로 전환해 처방한다(§7.4).
