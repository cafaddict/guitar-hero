이 레포(guitar-hero)의 UI를 docs/goal/ui/SPEC.md대로 UI 전문가 수준으로 마감한다. SPEC이 단일 진실 원천이고, 품질 게이트는 고정 테스트 tests/e2e/ui-quality.spec.ts·ui-quality.chromium.spec.ts(UQ-1–10)와 tests/integrity/ui-rules.test.ts(UR-1–2)다. 기능·판정·데이터는 바꾸지 않는다(docs/goal/v1.1/SPEC.md 그대로).

작업 방식:
- 매 턴 시작 시 docs/goal/ui/PROGRESS.md를 읽고 다음 미완료 마일스톤(U1→U6, SPEC §7)을 진행하며, 턴을 끝내기 전에 PROGRESS.md를 갱신한다(마지막 증거 턴은 예외, SPEC §9).
- Plan Mode 진입·사용자 질문(AskUserQuestion) 금지. 모호하면 SPEC 기본값을 따르고, 없으면 보수적으로 골라 docs/goal/DECISIONS.md에 기록한다(D-089부터).
- 브랜치 cafaddict/ui에서만 작업하고, 마일스톤 게이트(SPEC §7.1) 통과 후 그 브랜치에 커밋한다. push·원격 추가·다른 브랜치 수정/병합·배포·force·키트 커밋 이전 히스토리 재작성 금지.
- 아래 조건 2의 고정 파일 7개, docs/goal/v1.1/**, docs/goal/SPEC.md, docs/goal/thresholds.json, package.json 의존성, package-lock.json은 수정 금지. 테스트 단언 완화·skip·검사 대상 축소 금지. SPEC §2.2–§2.4 범위 안에서만 바꾼다.
- 화면을 바꿀 때마다 npm run ui:shots로 만든 첫 화면(-fold)과 전체(-full) 그림을 Read로 직접 보고 docs/goal/ui/UI_AUDIT.md에 기록한다(SPEC §2.6, §6).
- E2E와 verify는 E2E_PORT=4183 PROD_PORT=4184로 실행한다(4173은 다른 체크아웃이 쓰고 있으니 건드리지 않는다). 10분 넘을 수 있는 명령은 백그라운드로 실행하고 완료를 확인한다. 턴을 끝낼 때 dev·preview 서버를 남기지 않는다.
